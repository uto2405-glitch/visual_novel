# 비주얼노벨 스튜디오

잠들기 전, 책상 위의 야간 촬영장 / (촬영장·페이스 체크를 실사 사진으로). 감독의 조판 판정(컷 제목·꼬리 방향·페이지 나누기·표지 부제·배우 크롭)이
필름캔을 거쳐 새 기기에서도 복원되는지 이 대본 자체를 열어 확인합니다. 혼자 쓰고(대본실) · 혼자 찍고(촬영장) · 혼자 보는(시사실)
1인 비주얼노벨 제작 도구입니다. 모든 작업본은 **이 기기(브라우저 IndexedDB)** 에만 있습니다 —
소셜도, 공개도, 서버 저장도 없습니다.

## 실행

| 방법 | 명령 |
| --- | --- |
| **exe (권장)** | `release\VN-Studio.exe` 실행 → 브라우저가 `http://localhost:5173` 을 엽니다. 바탕화면 「비주얼노벨 스튜디오」 바로가기도 같습니다. |
| 개발 서버 | `npm install` 후 `npm run dev` |
| 빌드 + 로컬 서버 | `npm run build` 후 `node server.cjs` |
| exe 재빌드 | `npm run make:exe` (dist 내장, `release/VN-Studio.exe`) |

**폰에서 쓰기**: PC에서 exe를 켜 두고, 같은 와이파이의 폰 브라우저로
`http://<PC의 IP>:5173` (예: `http://192.168.219.104:5173`). 방화벽은
「VN-Studio (5173, LocalSubnet)」 허용 규칙이 잡혀 있습니다.

## 카메라 토큰 (MakeFun)

- 토큰은 **localStorage `makefun_token`** 에만 저장됩니다. 헤더의 ⚙ 설정에서 바꿉니다.
- `.env.local`의 `VITE_MAKEFUN_TOKEN`이 최초 1회 기본값으로 심어집니다.
  **exe를 남에게 줄 때는 `.env.local`을 지우고 다시 빌드하세요** — 토큰이 번들에 들어갑니다.
- 필름캔(ZIP)·시사본(HTML)에는 토큰이 **절대 포함되지 않습니다**.

### 비용 실측 (코인)

- Wan 2.7 ≈ 8 · Seedream 5 Pro ≈ 12~25 · 컷씬 영상(image2video) ≈ 30
- reuse 컷 / 플레이스홀더 / 내 파일 등록 = 0
- **실패해도 시작 시점에 과금**됩니다. 같은 사유(저작권 등)로 연속 NG면 배치가 스스로 멈추고,
  결과가 나왔는데 반영이 안 됐으면 「결과 찾아오기」로 무과금 회수합니다.
  배치는 두 컷을 동시에 찍으므로(동시성 2), 가드가 걸릴 때 한 컷이 이미 떠 있을 수 있습니다 —
  **낭비 상한은 동시성만큼**(2~3컷)입니다.
- Seedream이 실존 인물 사진을 저작권으로 거부하면 → 카메라를 Wan 2.7로 바꿔 「NG만 다시」.

## 백업 = 필름캔(ZIP)

브라우저 저장소는 영원하지 않습니다. **「내 기기로 내보내기」** 로 만든 `.vnproj.zip`이 곧 원본.
`story.json` + 배우 사진(`chars/`) + 생성 이미지(`generated/`) + 테이크(`takes/`) + 영상(`video/`)
+ 컷 상태(`cuts.json`) + 전속 배우단(`troupe/`)이 전부 들어 있고(인쇄본을 함께 넣으면
`webtoon/` 안에 페이지 PNG·PDF 한 부·인덱스 시트까지), 「내 기기에서 불러오기」로
그대로 복원됩니다 — **다른 기기에서도 배우가 따라옵니다.**

연재라면 시사실의 **📄 「장 이름」만** 버튼이 **지금 보고 있는 컷이 속한 장만** 담은 시사본을
내보냅니다 — 화마다 파일 하나로 주고 싶을 때 씁니다(그 장의 컷·그림만 들어가고 장 밖으로
이어지는 연결은 끊깁니다. 제목에 장 이름이 붙고 파일 이름에도 들어갑니다).

**「시사만 보내기」** 는 감상 전용 HTML 한 장 — 소리(앰비언스·음악 즉석 합성)·되감기·자동
상영·엔딩 크레딧 롤에 타자 속도·글자 크기 취향까지 담겨, 파일 하나로 어디서든 열어 볼 수
있습니다. 필름캔을 내보낼 때 「함께 넣기」를 고르면 ZIP 안에 `screening.html`로 동봉됩니다.

## 인쇄본 = 실사 웹툰

시사실의 **🖨 인쇄본 만들기**는 찍어둔 실사 컷을 만화 문법으로 조판합니다 — 말풍선(대사·생각·
외침), 내레이션 캡션, 컷 제목 라벨, 컷 테두리를 **앱이 Canvas로 직접 그립니다**(생성 모델은
한글을 흉내만 내므로 절대 맡기지 않습니다). 크레딧 0, 무한 재편집. 세로 스트립은 컷마다 원본
비율을 지켜 잘림이 없고, 2×2 그리드는 1:1로 자르므로 촬영을 **1:1 정사각**으로 하면 좋습니다.
효과선(속도선·집중선·섬광)은 프레임 가장자리에서 흘러들어오고 **인물이 서는 가운데는 비웁니다**
— 실사 사진에서 선이 얼굴을 가로지르면 효과가 아니라 실수로 보입니다. 집중선·섬광은 얇은 선이
아니라 **쐐기를 채워** 그립니다(사진 위에서는 선이 묻힙니다). 말풍선 **꼬리 방향**은 감독이
고릅니다 — 그림에서 인물 위치를 자동으로 찾으려 해봤지만 야간 실사에서 전광판을 인물로
오판했습니다(오차 0.47).
글자 크기·칸 간격·**종이색(흰/검 여백)**·**컷 번호(「1. 제목」 / 제목만)** 는 취향으로 기억되고, 맨 앞에 **📔 표지**(제목 아래는 대본실의 **표지 부제**(비우면 「N컷」)와 **표지 아래 한 줄**(지은이·발행일, 비우면 안 그림)), 맨 뒤에
**👥 등장인물**(캐스팅 사진으로 만든 인물 소개 — 이름·외모 메모·몇 컷 등장(다른 작품에도 나온 배우면 「「밤의 편지」 외 1편에도」), 6명 이상이면 2열)을
붙일 수 있습니다. 사진에서 얼굴이 남을 쪽은 캐스팅 카드의 **위·중·아래** 칩으로 고릅니다 —
비율로 자동 판정해봤지만 인물이 세로 가운데 있는 사진에서 얼굴이 잘렸습니다.
야간 실사 컷은 **검은 여백**이 어울립니다 — 컷이 필름처럼 떠 보이고 흰 말풍선이 살아납니다.
**🏷 컷 제목 채우기**로 한 장(또는 「모든 장」)의 제목을 한 번에 채울 수 있고(적어둔 제목은
덮지 않습니다. 「제목 지우기」로 이 장의 제목을 한 번에 비울 수도 있어요),
컷마다 **이 컷 글자**(작게/보통/크게)·**⏎ 새 장에서 시작**·**↺ 기본값**(그 컷 설정 전체 초기화)으로 장을 넘길 수 있어 절정 컷을 페이지 첫 칸에 둘 수 있습니다
(읽는 순서 자체는 대본의 연결을 따릅니다 — 조판이 순서를 바꾸면 시사와 조용히 어긋납니다).
시사본(HTML) 표지에는 «만화판도 함께» 타일이 붙습니다. 미리보기에서 **표지·본문·등장인물**을
모두 넘겨볼 수 있고(📔/1/2/👥 칩으로 바로 이동), 조판 수정은 조판실의 **↩ 되돌리기**로 물립니다. 컷마다 **🎬 촬영장에서 열기**가 있어
다시 찍을 컷으로 바로 갈 수 있습니다 — 조판실 안에는 촬영 버튼을 두지 않습니다(이 방은
크레딧을 쓰지 않는다는 약속을 지키기 위해), 보이는 장수 그대로 내보냅니다.
**🗒 인덱스 시트**는 모든 장을 한 장에 축소해 나열합니다 — 글자를 읽는 시트가 아니라
연재 전체의 리듬(어느 장이 길고 짧은지, 어디서 장이 열리는지)을 한눈에 보는 용도입니다.
장이 열리는 칸에는 **호박색 이름표**(1장 · 2장 · 「3장 · 새 이름」…)와 굵은 테두리가 붙어
20장 합본에서도 장 경계가 보입니다(표지·목차가 앞에 붙은 만큼 칸이 밀리는 것도 계산합니다).
**📜 긴 스크롤 한 장으로**는 장들을 세로로 이어 웹툰 플랫폼용 한 장을 만듭니다(너무 길면
나눠서 여러 장 — 조용히 잘리지 않습니다). 장 넘김은 캐시로 즉시(≈27ms)지만, 고친 값이
지문에 들어가 있어 **수정은 반드시 다시 그립니다**. **📄 PDF 한 파일로**는 장들을 PDF로 묶습니다
— 라이브러리 없이 직접 씁니다(JPEG를 그대로 품는 구조라 exe가 무거워지지 않습니다).

## 장기 연재

> **장으로 하는 일 한 눈에** — 만들기(컷 카드 ⏎ 새 장) · 이름(촬영장 ✎ 장 이름) ·
> 순서(정리대 ▲▼) · 합치기(⤺) · 다음 화로(▶) · 찍기(이 장만 촬영 · 이 장 NG만 다시 ·
> 크레딧 어림값) · 보기(시사실 장부터 · ⏹ 장 끝에서 멈춤 · 장별 진도 판 · 필름 맵 이름표) ·
> 내보내기(인쇄본 📖·📜 · 시사본 📄 · 필름캔 읽어보기.txt) · 다시 쓰기(✎ 다시 쓰기 →
> 다시 쓴 대본 넣기) · 찾기(캐스팅 «나온 장» · 배우단 «어느 작품 몇 장» · 리포트 «3장 · s37 보기»).
> 앱 안에서는 **감독 수첩(?) → 「장으로 하는 일」** 절에 같은 지도가 있습니다.

**장(chapter)의 기준은 한 곳뿐입니다** — 컷의 **⏎ 새 장에서 시작**입니다. 대본실·촬영장·시사실·
콜시트·인쇄본이 모두 이 기준을 쓰므로 「인쇄본의 3장」과 「촬영장의 3장」이 어긋나지 않습니다.
세는 코드도 한 곳입니다(`src/lib/chapters.ts`) — 같은 규칙을 네 군데에 베껴 두면 언젠가 어긋납니다.

**장을 통째로 다룹니다**(대본실 정리대의 장 줄, 장을 하나 고르면 나옵니다).
조판실에는 **📖 「장 이름」만**(쪽 PNG) · **📜 「장 이름」만 긴 스크롤**(플랫폼 업로드용 한 장) ·
**📄 「장 이름」만 PDF**(인쇄소·메일용)가 있어 지금 보고 있는 쪽이 속한 장만 따로 뽑습니다 —
연재는 화마다 파일 하나로 올리니까요(표지·목차·등장인물 장은 빠지고, 파일 이름에 장 이름이
붙습니다. 「전체 N장」 버튼은 그대로 책 한 권을 냅니다).

- **▲ 장 앞으로 / ▼ 장 뒤로** — 「3장을 4장 뒤로 미루자」를 한 번에. 컷이 블록째 따라오고
  「⏎ 새 장에서 시작」 표시는 다시 매겨집니다(첫 장에는 표시가 남지 않고, 앞으로 나온 장에는
  붙습니다 — 그래서 옮겨도 장 수가 늘거나 줄지 않습니다). 그림·대사·연결은 그대로입니다.
- **⤺ 앞 장과 합치기** — 「이 장은 너무 짧다」는 판단은 대본을 보며 내리는데, 장을 여는 표시는
  조판실에만 있었습니다. 컷은 그대로 두고 나누기만 없앱니다.
- **▶ 다음 화로** — 「이 장은 이번 화에 안 들어가겠다」를 한 번에. 그 장의 컷이 이 작품에서 빠져
  새 화의 **첫 장**이 되고, 화풍·감독 노트·배우(캐스팅 사진째)가 따라갑니다. 빠진 장을 가리키던
  연결은 **그 다음 컷으로 이어 붙입니다**. **아직 찍지 않은 장만** 보냅니다 — 찍은 필름이 화를
  넘어가면 그림·테이크가 어느 작품에 있는지 헷갈리기 때문입니다(찍은 장은 버튼이 막히고
  이유를 말합니다. 순서만 바꿀 거면 ▲▼를 쓰세요).
- **✎ 장 이름**(촬영장) — 장 이름은 그 장 첫 컷의 컷 제목입니다. 그 컷을 찾아 들어가지 않고
  고치며, 인쇄본의 장 제목 띠·목차도 같이 바뀝니다.
- **컷 카드의 ⏎ 새 장** — 장을 나누는 자리가 조판실에만 있었는데, 장은 인쇄본만의 것이 아니라
  촬영·시사·콜시트가 함께 쓰는 단위입니다. 이야기를 쓰는 자리에서 바로 나눕니다(첫 컷은 표시가
  없어도 1장이라 눌리지 않습니다).
- 촬영장에서 장을 고르면 **이 장 NG만 다시 (N)** 버튼이 함께 나옵니다(NG가 있을 때만) — 장 단위
  재촬영은 연재에서 흔하고, 대기 컷은 건드리지 않습니다.
- 필름 맵에는 장 첫 컷 위에 **장 이름**이 얹힙니다 — 100컷 지도에서 「어디서 3장이 시작하나」가
  보이게. (지도는 이야기 순서가 아니라 갈래 깊이로 열을 잡으므로 선을 긋지 않고 이름을 얹습니다)
- 촬영장에서 장을 고르면 「이 장만 촬영」 옆에 **이 장의 크레딧 어림값**이 나옵니다(지금 카메라
  기준, reuse·내 파일 컷은 0으로 셈). 연재는 「이번 장에 얼마 드나」로 예산을 가늠합니다.
- 정리대(카드·목록 두 보기 모두)에는 **장 머리글**이 들어갑니다 — 60컷 목록에서는 「몇 번째 컷」보다
  「몇 장」으로 찾게 됩니다. 내보낸 시사본 목록도 같은 이름으로 갈립니다.
- 옮기기·합치기·이름은 **↩ 되돌리기**로 돌아옵니다(2초 안에 같은 장을 두 칸 민 것은 한 걸음으로
  묶입니다). 다음 화로 보낸 것은 새 화가 만들어지므로 되돌리기 대상이 아닙니다 — 그래서 확인창을
  먼저 띄웁니다.
- **「↩ 되돌리기 (3)」의 숫자는 «이 편»의 걸음 수입니다.** 되돌리기 스택은 창 하나에 편을 가리지 않고
  쌓입니다. 예전에는 그 전체 길이를 적어서, 「가 편」에서 세 번 고친 뒤 다른 편으로 옮기면 새 편에
  「(4)」가 떠 있었고 눌러 봐야 남의 걸음이었습니다(실측). 그리고 되돌릴 때 위에 쌓인 남의 걸음을
  버리며 내려와, 편을 오가며 일하면 **돌아온 편의 되돌리기가 조용히 사라졌습니다** — 이제 자기 걸음만
  꺼내므로 두 편의 되돌리기가 나란히 살아 있습니다. 새로고침하면 스택이 없어지고 딱지도 0으로
  정직해집니다(세션 메모리이므로 저장되지 않습니다 · `undoscope` 스위트).

연재는 두 가지로 씁니다 — 둘 다 검증돼 있습니다(`serial` 스위트).

- **한 작품 안에 여러 장**: 장 첫 컷에 **⏎ 새 장에서 시작**을 켜면 인쇄본이 장마다 나뉩니다
  (5장 60컷 → 본문 5장; `SERIAL_CHAPTERS=10`으로 10장 120컷까지 재봤습니다). 필름 맵은 여덟 열을 넘으면 줄바꿈되어 60컷도 한 화면에 들어옵니다.
  **20장 240컷까지** 재봤습니다(`SERIAL_CHAPTERS=20 node serial.cjs`, 82체크 전부 그린) —
  반영(파싱 + 카드 240장 렌더) **0.97초**, 장별 진도 판 20줄, 목차 20항목(1208×1230),
  지도는 240컷에서도 가로 1화면, AI 이어쓰기 프롬프트 6KB, 인쇄본 21장(장 넘김 6.7초),
  대본실 재렌더 0.78초, 컷 한 줄 타이핑 0.12초.
  (초기 측정에서 13.3초가 나온 것은 테스트가 58KB를 textarea에 채우는 시간 7.4초를 함께 센
  탓이었습니다 — 앱 성능이 아닙니다. 성능은 「반영」을 누른 뒤부터 재야 정직합니다)
  인쇄본에는 **찍은 컷만** 담기므로, 장마다 한 컷이라도 찍혀 있어야 그 장이 나옵니다.
  장이 열리는 페이지에는 **📖 장 제목 띠**가 얹혀(컷 제목을 표제로 크게) 합본에서도 장이 보이고,
  장이 다섯을 넘으면 표지 다음에 **🗂 목차**(장 제목 · 점선 리더 · 쪽번호) 한 장이 붙습니다.
  목차 줄에는 장 제목 옆에 **그 장의 컷 수**가 옅게 붙습니다(「봄비 12컷 ……… 3」) — 합본에서
  어느 장이 두꺼운지가 목차만 봐도 읽힙니다.
  목차는 **1장부터** 싣고(첫 컷은 표시가 없어도 1장입니다), 이름을 안 붙인 장은 **「N장」**으로
  실립니다 — 목차에서 장이 빠지면 몇 장짜리 책인지가 어긋납니다.
- **AI 이어쓰기는 뒤 18컷만 싣습니다**: 대본 전체를 붙이면 10장 120컷에서 30KB, 20장이면 60KB
  (약 2.5만 토큰)가 됩니다. 인물·화풍·감독 노트와 최근 흐름만 실고, 앞은 「전체 N컷 중 마지막
  18컷만 실었다」로 알립니다. 새 장을 여는 방법(`pageBreak`)도 규칙에 들어 있습니다.
- 캐스팅 카드에는 **이 배우가 나온 장**이 한 줄로 붙습니다(장이 둘 이상일 때) — 연재가 길어지면
  「하나가 언제 나왔더라」를 대본을 훑어 찾게 됩니다. 장 이름을 누르면 **정리대가 그 장만** 보여줍니다.
  아직 어느 컷에도 등장 배우로 켜지 않았으면 그렇다고 말해줍니다.
- 최근 프로젝트 목록에는 화마다 **진행 막대**(찍은 컷/전체)와 필름캔 표시(🎞)가 붙어
  «어느 화가 어디까지 됐나»가 한눈에 보입니다. 폰(390px)에서도 줄이 넘치지 않고 막대가 폭을
  갖습니다(실측: 막대 161×3px·채움 33%, 열기 버튼 58px — `mobile` 스위트가 지킵니다).
- **▶ 다음 화 만들기**: 지금 작품의 화풍·감독 노트·배우(캐스팅 사진째)를 물려받은 새 화를
  한 걸음으로 만듭니다. 제목은 「…2화」→「…3화」로 이어 제안하고, **앞 화의 마지막 세 문장**을
  감독 노트에 남겨 둡니다 — 다음 화를 쓸 때 앞 화를 다시 열지 않아도 되고, AI 이어쓰기
  프롬프트에도 그 노트가 함께 실립니다.
- **화 이름은 감독이 짓는 대로 읽습니다** — 앱이 짓는 이름은 「우산 3화」지만, 「1편」·「3회」·「12부」와
  **「01화」(자릿수를 지켜 「02화」)**, 괄호 안 **「(상)→(중)→(하)」**, 표기 없는 끝 숫자(「서점 3」→
  「서점 4」)까지 한 곳(`lib/episodes`)에서 읽습니다. 예전에는 이런 이름이 조용히 연재에서 빠져
  「비 오는 정류장 1편 2화」 같은 이름이 나왔고, 엔딩의 이어보기·합본에서도 남이었습니다(실측).
  **읽지 않기로 한 것**도 분명합니다 — 「소년 1994」는 연도이지 화가 아니고(네 자리 끝 숫자),
  괄호 없는 「최우수상」은 「상」이 아닙니다. **표기가 다르면 남입니다**: 「정류장 1편」과
  「정류장 2화」는 한 권으로 묶이지 않습니다. 「(하)」처럼 다음 이름이 없는 자리에서는 짐작하지 않고
  일반 규칙(「… 2화」)으로 물러섭니다 — 이어보기는 짐작 대신 **목록에 실제로 있는 다음 편**을
  가리킵니다(`epname` 스위트).
- 배우단 선반은 뜻이 다른 두 숫자를 **각자 이름을 달아** 적습니다 — **「1편에 나옴」**(저장된 작품을
  훑어 센 «컷 등장» 편수, 아래 작품 목록과 같은 근거)과 **「데려온 5편」**(배우단에서 캐스팅한 횟수).
  하나만 남기면 「데려왔지만 아직 안 쓴 화」가 사라지고, 이름을 안 달면 어느 쪽도 믿을 수 없습니다.
- 배우단 선반에는 배우마다 **어느 작품 몇 장에 나왔나**가 붙습니다(「역의 우산」 1·3장 · 12컷) —
  「N편 출연」 숫자만으로는 찾을 수 없던 것입니다. 선반을 열 때 저장된 작품을 한 번 훑어 셉니다.
  그 **작품 이름을 누르면 그 편이 열립니다** — 알고 난 다음의 손짓은 «거기로 가자»이고, 20편에서
  목록을 다시 뒤지게 할 이유가 없습니다. 지금 열려 있는 편은 누를 것이 없으므로 「· 지금 이 편」으로
  표시만 합니다. 세 편을 넘으면 **「외 4편 ▾」을 눌러 전부 펼칠 수 있습니다**(기본은 접힘 —
  배우가 여럿이면 선반이 길어집니다). 여덟 화짜리 연재에서 여섯 편이 그 접힘 속에 묻혀 있었고,
  묻힌 편은 누를 수도 없었습니다(실측). 선반은 **편이 바뀌거나 대본이 바뀌면 다시 셉니다** —
  지금 열린 편은 저장을 기다리지 않고 메모리의 것으로 세므로, 방금 반영한 화도 바로 잡힙니다.
- 인쇄본 **등장인물 장의 「출연」 칸도 이름으로 적습니다** — 「2컷 등장 · 「밤의 편지」 외 1편에도」
  (이 책 제목은 뺍니다). 근거는 선반과 같은 한 번의 훑기입니다. 칸이 좁아 제목이 안 들어가면
  **후퇴를 단계로** 둡니다: 「「밤의 편지」 외 1편에도」 → (안 들어가면) 「에도」를 떼고 → 제목을 잘라
  「「겨울에 시작해서…」」 → 그래도 안 되면 「다른 2편에도」 → 마지막에 컷 수만. 한 번에 컷 수로
  떨어지면 이력이 통째로 사라지기 때문입니다 — 배우 6명 이상(2열)이면 글자칸이 388px로 좁아져
  「「밤의 편지」 외 1편에도」(423px)가 안 들어가고, 예전 구현은 그 자리에서 「2컷 등장」만 찍었습니다(실측).
  카드 밖으로 넘친 글자는 아래 카드 이름 위에 겹쳐 찍히므로 «넘치는 쪽»이 가장 나쁩니다.
- **감독 노트는 화를 넘어 자라지 않습니다** — 「다음 화 만들기」는 앞 화의 노트를 물려주고
  **앞 화의 마지막 세 문장**을 요약으로 붙이는데, 예전에는 그 요약이 계속 쌓여 6화 노트에 블록이
  다섯 개(328자·22줄)였고 AI 이어쓰기 프롬프트에도 지난 화 대사가 전부 실렸습니다(실측). 이제
  **가장 최근 요약 하나만** 남습니다(6화에서도 94자·1블록, 프롬프트 2,032자 → 1,781자) — 감독이
  손으로 쓴 규칙은 그대로 둡니다.
- **화마다 작품 하나**: 배우를 **⭐ 전속 배우단**에 올려두면 사진째로 데려옵니다
  (5화까지 «5편 출연»으로 셉니다). 기기를 옮길 때 **🎞 모두 내보내기**로 전 화를 한 번에 챙기고,
  **필름캔마다 배우단이 함께 담기므로** 새 기기에서 다음 화를 바로 이어 쓸 수 있습니다.

**저장 공간이 꽉 차면 분명히 말하고, 들고 나갈 길을 알려 줍니다** — 할당량을 4MB로 줄여
실제로 부딪혀 본 실측입니다. 컷을 걸 때 나오는 「걸었습니다 — OK」는 «메모리에 걸렸다»는 뜻이고
저장은 뒤에서 따로 일어납니다: 그림 스물넉 장을 걸었을 때 저장소에 들어간 것은 **0장**이었습니다.
예전 알림은 「저장하지 못했습니다 … ()」로 빈 괄호를 달고 무엇을 하면 되는지 말하지 않았습니다.
저장은 이제 **묶음으로 나눠 씁니다** — 예전에는 한 트랜잭션에 전부 담아, 자리가 모자라면
«들어갈 수 있던 것까지» 통째로 취소됐습니다(24장 중 **0장**). 지금은 들어가는 데까지 남고
알림이 **「24장 중 12장은 저장했습니다」**라고 몇 장까지 됐는지 말합니다.
이제 **「저장 공간이 가득 찼습니다 — 오늘 촬영분이 아직 저장되지 않았습니다. 🧹 저장소 청소나
페이스 체크의 「옛 테이크 비우기」로 자리를 만들거나, 먼저 «내 기기로 내보내기»로 필름캔을
챙겨두세요.」**라고 말하고, 제목 옆 점이 **붉게** 바뀌어 이유를 답니다(마우스를 올리면 문장으로
읽힙니다). 그리고 **꽉 찬 상태에서도 필름캔(ZIP)은 나옵니다** — 저장이 막혀도 손에 들고 나갈
길은 열려 있습니다. 대본도 그대로 고쳐지고 새로고침해도 앱이 열립니다.
**자리를 만들어도 브라우저가 곧바로 돌려주지 않을 수 있습니다** — 실측에서 테이크 16장을 지워
저장소가 0장이 됐는데도 사용량은 3,825KB 그대로였고, 8초 뒤에도 새로고침 뒤에도 같았습니다.
그래서 저장이 막힌 상태에서 🧹를 누르면 「약 3.7MB 확보」 뒤에 **「다만 브라우저가 그 자리를
곧바로 돌려주지 않을 수 있습니다 — 저장이 계속 안 되면 «내 기기로 내보내기»로 먼저
챙겨두세요」**를 덧붙입니다(평소에는 붙이지 않습니다 · `quotafull`·`takes100` 스위트).

**며칠 켜 두어도 조용히 무거워지지 않습니다** — 새로고침 없이 편 전환 100회·방 이동 300회·
대본 전체 반영 20회(100컷 작품 셋)를 316초에 몰아 돌린 실측입니다: JS 힙 10MB, DOM 노드 79,089,
이벤트 리스너 1,861이 **한 자리도 움직이지 않았고** 저장도 그대로였습니다(새로고침 뒤 마지막 글이
남아 있습니다). 고칠 것이 없어 그대로 두고, 그 «평평함»을 `longrun` 스위트로 지킵니다 —
이 스위트는 **자기 계측기부터 시험합니다**(일부러 만든 노드 2만·리스너 2만 누수가 잡히는지).

**줌인·줌아웃이 «같은 장면»으로 이어집니다** — 이 앱에 줌 필드는 없고, 줌은 shot 사다리
(`wide → full → portrait → focus`)로 만듭니다. 그런데 예전에는 `focus`·`portrait`가 `bg_prompt`를
쓰지 않아서, 줌 사다리의 뒤쪽 컷에서 장소가 사라졌습니다. **실촬영 A/B**(6컷·72크레딧)로 그 결과를
눈으로 확인했습니다: 같은 교실을 당겨 찍은 반신 컷이 **밤거리 상점 유리**로 바뀌어 줌인이 장면
전환처럼 보였고, 같은 컷에 장소를 얹은 쪽은 교실이 흐리게 남아 이어졌습니다. 그래서 이제
`focus`·`portrait`도 장소를 **「흐린 배경」으로 얹습니다**(프레이밍 지시 뒤에 붙여 구도를 밀어내지
않습니다). 장소를 일부러 지우려면 그 컷의 `bg_prompt`를 비우면 예전 그대로입니다.
함께 고친 것: 촬영장 컷 카드가 **실제 shot을 그대로** 적습니다(예전에는 `focus`가 아니면 전부
「full」로 적어서, 줌 사다리를 짜 놓고도 카드에서 알 수 없었습니다). 연속동작은 `hold`로
앵글·의상·소품·자리를 고정하고, 같은 장면은 `bg_prompt` 문구를 그대로 복사하며, 같은 그림은
`bg:"reuse:…"`로 크레딧 0에 복사합니다(`zoomchain` 스위트가 이 사슬을 지킵니다).

**인터넷이 끊겨도 작업은 계속되고, 나간 코인은 장부에 남습니다** — exe는 로컬 서버라 앱은
오프라인에서도 돕니다(대본을 고치고 저장하고, 새로고침해도 그대로입니다). 카메라만 인터넷인데,
끊김을 세 갈래로 실측했습니다: ① **시작 요청이 아예 못 나가면** 컷을 NG로 몰지 않고 「⏳ 지연」으로
두고 「카메라와 연결이 잠시 끊겼습니다. NG가 아니라 아직 만드는 중일 수 있어요 — 잠시 후
「결과 찾아오기」로 가져오거나 이 컷만 다시 찍어보세요」라고 컷에 적습니다(과금이 없었으니 장부도 0).
② **시작은 접수되고 그 뒤 끊기면** 그 8코인이 장부에 남습니다. ③ **완성된 그림을 받아오는 길만
끊겨도** 역시 남습니다. 다시 이어지면 그대로 촬영됩니다(`offline` 스위트).

**느린 기계에서도 촬영장·시사실·조판실은 그대로입니다** — CPU를 4배 느리게 걸고 600컷으로
재봤습니다: 촬영장은 1.2초에 열리고(막힘 1.1초) 컷 카드 600개가 노드 15,414개(컷당 26개)여서
훑기 끊김 0, 시사실은 막힘 0.33초, 조판실은 2.9초에 열리며 0.5초 넘는 막힘이 0회입니다.
손댈 것이 없었고, 그 값을 `slowrooms` 스위트가 지킵니다(스위트의 첫 체크는 앱이 아니라
**계측기**를 시험합니다 — 일부러 만든 400ms 막힘을 못 잡으면 나머지 값은 뜻이 없습니다).

**컷이 300개를 넘는 편은 「☰ 목록」 보기로 엽니다** — 느린 기계를 흉내 내 재봤습니다(CPU 4배 느리게).
600컷을 카드 보기로 열면 반영이 **8.5초** 멈추고 훑기 끊김이 17회였는데, 목록 보기는 **0.3초**
(막힘 591ms)·끊김 0에 문서 노드도 3,286개(카드 394,508개)였습니다. 그래서 긴 편은 가벼운 쪽으로
열고 **「컷이 600개라 「☰ 목록」 보기로 열었습니다 — 카드 보기로 바꿀 수 있어요」**라고 말합니다.
카드 보기 문은 바로 옆에 있고, 감독이 기억시킨 보기 설정은 덮지 않습니다(이 편에서만 가볍게 엽니다).
240컷까지는 예전 그대로 카드 보기입니다(4배 느린 기계에서도 반영 1.2초·끊김 0).

**한 편에 600컷(장편 한 권)을 담아도 섭니다** — 실측입니다: 반영 1.1초 · 저장 0.23초 ·
필름캔 0.3초 · AI 이어쓰기 프롬프트 5,327자(600컷을 다 싣지 않고 눌러 담습니다) · 훑기는
DOM 394,508노드에서도 중간 17ms에 끊김 0회 · 500번째 컷으로 뛰면 그 자리에 서고 튀지 않습니다.
무거웠던 곳은 **반영**이었습니다: 화면이 **3,028ms 통째로 막히고 아무 말이 없었습니다**.
두 가지로 고쳤습니다 — ① 화면 밖 컷 카드는 배치·그리기를 미루고(`content-visibility`, 막힘
**1,476ms**로 절반. 240컷도 600 → 300ms), ② 멈추기 **전에** 단추가 「반영 중…」으로 바뀝니다
(무거운 일을 시작하기 전에 한 번 그리게 합니다 · `cuts600` 스위트).

**폰(390px)에서 600컷도 같은 값을 냅니다** — 반영 1.2초(멈춤 1.6초, 「반영 중…」 표시),
훑기는 중간 17ms에 끊김 0회, 500번째 컷으로 뛰면 그 자리에 섭니다. 하나 어긋나 있던 것은
**어림 높이**였습니다: 화면 밖 카드를 데스크톱 값으로 어림하니(폰 카드는 실측 **858px**인데 340px)
훑는 동안 문서가 **204,679 → 526,367px(157%)** 자라 스크롤바를 반쯤 끌면 엉뚱한 자리에
섰습니다. 폰용 어림(860px)을 따로 두어 **-3%**가 됐고, 데스크톱도 실측 가운데값(340px)으로
옮겨 13% → **1%**가 됐습니다(`phone600`·`cuts600` 스위트).

**폰(390px)에서도 낭독기로 쓸 수 있습니다** — 실측했습니다: 낭독 순서의 첫째가 「작업 영역으로
건너뛰기」이고(그것을 쓰면 첫 컷까지 11탭, 없으면 49탭), 랜드마크는 머리·길잡이·방 각 하나,
세 방의 보이는 단추 136개 중 **이름 없는 것 0개**입니다. 하나 어긋나 있던 것은 제목 계단이었습니다 —
작품을 열면 화면의 제목이 모두 h2여서 **「제목 1」로 갈 곳이 없었습니다**. 방 머리에 낭독 전용
h1(「작품 이름 — 방 이름」)을 두었습니다(화면에서는 1px로 잘려 보이지 않고, 방을 옮기면 함께
바뀝니다 · `phonea11y` 스위트).

**깨진 필름캔을 넣어도 지금 작업은 멀쩡합니다** — 몇 달 뒤 ZIP만 남았을 때가 진짜 시험입니다.
일곱 가지를 실측했습니다: 대본이 없으면 「ZIP 안에 story.json이 없습니다 — 필름캔이 아닌 것
같습니다」, 잘렸으면 「올바른 JSON이 아닙니다」, 컷이 없으면 「장면이 하나도 없습니다」라고 말하고
**열려 있던 작품은 그대로**입니다. 판정 파일(cuts.json)이 없어도 그림으로 되살아나고(OK 1),
훗날 버전의 낯선 필드는 무시하고 들여오며, 그림만 사라진 캔은 **대본을 살리고 OK 0으로 정직하게**
셉니다. 남의 ZIP은 필름캔이 아니라고 말합니다. 일곱 번을 잇달아 넣어도 페이지 오류는 0이었습니다.

필름캔 안에는 **읽어보기.txt**가 함께 담깁니다 — 폴더마다 무엇이 들었는지, **장 목록**(장 이름 ·
컷 범위 · 그 장에서 찍은 수), 다시 여는 법이 적혀 있어 몇 달 뒤 ZIP만 남아도 스스로를 설명합니다
(토큰은 여기에도 담기지 않습니다).

기기를 옮길 때는 **최근 프로젝트 → 🎞 모두 내보내기**로 모든 작품을 각자의 필름캔으로 한 번에
꺼내고, 새 기기에서는 **내 기기에서 불러오기에 ZIP 여러 개를 한 번에** 골라 되돌립니다
(스무 편을 스무 번 클릭하게 만들면 그건 이사가 아닙니다 — 편마다 알림 대신 끝에 한 줄로 요약합니다).
「전부 사본으로」를 고르면 제목에 **「(사본)」**이 붙습니다 — 같은 제목이 두 줄이면 목록에서
어느 쪽인지 알 수 없기 때문입니다(이미 「(사본)」이 있으면 「(사본 2)」로 올라갑니다).

같은 필름캔을 **다시** 넣으면 알아봅니다 — 필름캔의 지문(meta.json의 projectId)을 들여올 때
그대로 물려받기 때문입니다(다른 기기에서 만든 필름캔도 마찬가지). 여러 개면 **한 번만** 묻습니다:
「이미 있는 필름캔 N개 — 전부 교체 / 전부 사본으로」(스무 편마다 물으면 이사가 막힙니다).

**20화 실측**(`move20` 스위트): 20편 내보내기 3초(편당 129ms) · 새 기기 복원 1초 ·
제목·배우 얼굴·찍은 그림·장 구조 전부 복원 · 생성 호출 0 · 같은 필름캔 재투입은 한 번만 질문(작품집 하나로 묶지 않습니다 — 새 ZIP 구조와 새 가져오기 경로가 필요해
위험만 늘고, 이사에 필요한 것은 «전부 다 챙기기»입니다).

**쉰 편에서도 벽이 없습니다** — 실측(50편 200컷): 목록 50줄 렌더 **44ms**(목록칸 340px 안에서
스크롤), 검색 **336~348ms**(20편과 같습니다 — 훑기가 가벼워서), 합본 52쪽 22.8MB 7초,
JS 힙 32MB, 저장소 31MB.

**🔎 연재에서 찾기** — 대본실에 「연재에서 찾기」 판이 있습니다(작품이 둘 이상일 때). 두 글자
이상을 넣으면 **저장된 작품 전부**의 대사·컷 제목·말풍선을 훑어 「우산 2화 · 앞장 · 대사 …노란
장화이 여기 있습니다」처럼 보여주고, 누르면 **그 편을 열어 그 장으로 맞추고 그 컷까지** 데려갑니다.
줄마다 **그 컷을 찍었는지**(「· ✓ 찍음」 / 「· NG」 / 「· 대기」)도 적습니다 — 찾은 다음의 손짓은
«고치기»거나 «찍기»이고, 그러려면 상태를 알아야 그 편을 열지 말지 정할 수 있습니다.
20편 240컷이 쌓이면 「그 대사가 몇 화였지」가 실제 질문인데 답할 곳이 없었습니다.
실측(20편 240컷): 첫 검색 **553ms**, 이후 **~345ms**. 지금 열린 편은
저장을 기다리지 않고 메모리의 것으로 찾으므로 방금 고친 대사도 걸립니다. 타자를 멈춘 뒤에 찾고
(글자마다 저장소를 훑지 않게), 한 컷은 한 줄로, 예순 줄까지만 보여줍니다.

**📖 합본** — 최근 프로젝트를 펼치면 「📖 합본 (5편)」이 있습니다(같은 앞머리의 화가 둘 이상이고
찍은 컷이 있을 때만). 「우산 1화 · 우산 2화 …」를 번호 순서로 **한 권으로 조판해 PDF 한 파일**로
냅니다 — 표지 한 장·장 목차 한 장·등장인물 한 장을 책 전체에 두고, **쪽 번호를 이어 셉니다**
(각 화의 발치가 「3 / 42」가 됩니다). 화마다 따로 뽑으면 표지도 목차도 쪽 번호도 다섯 벌이 되어
책장에 꽂을 한 권이 없었습니다. 화가 바뀌는 자리는 **화 제목 띠**로 표시하고(원본 대본은 건드리지
않습니다), 아직 한 컷도 안 찍은 화는 **조용히 건너뜁니다**. 목차는 **화와 그 안의 장을 두 단으로**
싣습니다(「우산 1화」 아래 「· 우산 1화 뒷장」) — 화만 실으면 화마다 장이 둘인 책에서 목차가 절반만
보였습니다(실측). 줄이 마흔을 넘으면 화만 싣습니다(목차 한 장이 끝없이 길어지지 않게).
누르기 전에 **얼마나 큰 책이 되는지** 어림해 알려 줍니다(「대략 43쪽 · 35MB · 10초쯤」) —
쪽은 «편마다» 세어 더합니다(전체 컷을 한 번에 나누면 화가 바뀌는 자리를 두 번 세어 과대평가됩니다:
2편 4컷에서 6쪽이라던 것이 실제 4쪽이었습니다). 폰(390px)에서도 확인창이 화면에 들어가고
버튼은 44px입니다.
용량은 «쪽»이 아니라 «컷» 수를 따릅니다(한 쪽에 컷이 둘이면 넷일 때의 절반) — 실측 두 점에서
상수를 잡았습니다: 5화 40컷 = 13쪽·9.0MB·2초, **20화 160컷 = 43쪽·35.3MB·10초**(JS 힙 45MB),
**50화 100컷 = 52쪽·22.8MB·7초**(JS 힙 32MB · 저장소 31MB). 쉰 편도 한 번에 묶입니다. 등장인물은 이름으로 합쳐 컷 수를
더합니다. 크레딧은 들지 않습니다.

**엔딩에서 다음 화로** — 막이 내리면 크레딧에 「▶ 다음 화 보기 — 「우산 2화」」가 나옵니다(찍은 컷
수도 함께). 누르면 그 화를 열고 **처음부터** 상영합니다 — 지금까지는 시사실을 나가 목록을 열고
다음 화를 찾아 다시 시사를 눌러야 했습니다(네 걸음). 다음 화가 없거나 **아직 한 컷도 안 찍었으면
조용합니다**(보여줄 것이 없으니까요). 화 번호 규칙(「…3화」 → 「…4화」)은 「다음 화 만들기」와
**같은 한 곳**(`lib/episodes`)을 씁니다 — 만들 때와 이어 볼 때가 어긋나면 연재가 끊깁니다.
번호가 비어 있어도(4화를 지웠어도) 다음으로 큰 화로 잇습니다. **자동 상영으로 보고 있었다면
다섯을 세고 스스로 넘어갑니다**(「(5초 뒤 자동)」) — 손을 놓고 보던 관객에게 「직접 누르세요」는
끊김이니까요. 「여기서 멈추기」로 세는 것만 끊을 수 있고, 그러면 누르는 길만 남습니다.
자동 상영을 켜지 않은 사람에게는 세지 않습니다 — 재촉이 아니라 이어보기입니다. 편을 옮기면 **엔딩·장 끝 표시는
함께 걷힙니다** — 크레딧이 뜬 채로 다른 편을 열면 새 편이 「막이 내렸습니다 · OK 0컷」으로
시작하던 것을 실측으로 잡았습니다.

**연재 전체 진도** — 최근 프로젝트를 펼치면 목록 위에 한 줄이 있습니다: 「연재 전체 20편 · 240컷
중 187컷 OK (78%) · 다 찍은 편 12 · 제작비 1,240코인」. 제목이 한 연재로 모이면 「연재 전체」,
여러 작품이 섞여 있으면 「저장된」이라고 적습니다 — 합계는 언제나 이 브라우저의 모든 편이므로
이름이 그 사실과 어긋나지 않아야 합니다. **제작비**는 편마다의 크레딧 장부를 더한 값이고, 그 사본이
없는 옛 목록의 편은 합계에서 빼고 그 수를 밝힙니다(「3편은 아직 모름」) — 모르는 것을 0으로 세면
총액이 거짓이 됩니다. 편마다 진행 막대는 있었지만 «연재 전체가 어디까지»는 어디에도
없었습니다 — 20편을 쓰는 사람의 첫 질문이 그것입니다. 목록이 이미 들고 있는 수를 더한 값이라
편별 줄(「장면 12 · OK 9」)의 합과 언제나 같습니다(move20이 그 합을 맞춰 봅니다).

**두 창을 열어 두어도 작업이 사라지지 않습니다** — 저장소는 브라우저 하나에 하나뿐이라, 두 창이
같은 작품을 열고 각자 고치면 예전에는 **나중에 저장한 창이 기록 전체를 덮어써** 다른 창의 편집이
아무 말 없이 사라졌습니다(실측으로 잡았습니다). 이제 저장 직전에 기록의 시각을 보고, 내가 본
것보다 새로우면 **덮어쓰지 않고** 알립니다: 「다른 창에서 이 작품이 저장됐습니다 — 이 창의 변경을
덮어쓰지 않았어요. 「다른 이름으로 저장」으로 이 창의 것을 남기거나, 새로고침해서 최신본을
여세요.」 그 창의 편집은 화면에 그대로 남아 있으므로 사본으로 건질 수 있습니다.

**크레딧 장부는 편을 옮겨도 남습니다** — MakeFun은 시작 순간에 과금하는데, 촬영 중에 다른 편을
열면 그 순간 도착한 «시작된 컷의 크레딧»이 메모리에서 통째로 사라졌습니다(24코인이 장부에서
없어지는 것을 실측으로 잡았습니다). 이제 과금이 확인되는 자리에서 **그 편의 기록에 바로** 남깁니다
— 지금 열린 편이면 메모리와 기록 둘 다에(총액을 그대로 쓰므로 두 번 세지 않습니다), 이미 옮겼으면
그 편의 기록에 직접.

같은 규율을 **컷씬(영상)**에도 넣었습니다 — 영상은 컷당 수십 코인이라 잃으면 더 아픕니다.
라이브러리(`makefun/video.ts`)가 «시작이 접수된 뒤의 모든 실패·중단»에 크레딧을 실어 보내고,
배치·단발 두 경로가 그 편의 장부에 남깁니다(실측: 16 + 30 = 46코인).

**촬영 중에 다른 편을 열면** — 촬영은 멈추고(그 편의 OK 컷은 그대로), 그때 **이미 시작된 컷**은
「⏳ 지연」으로 표시해 둡니다. MakeFun은 시작 순간에 과금하므로, 표시가 없으면 돌아와서 그 컷을
「대기」로 보고 다시 찍게 됩니다 — 같은 그림에 두 번 냅니다. 옮길 때 「「이번 화」에서 찍던 2컷은
이미 시작돼 과금됐습니다 — 그 편의 「결과 찾아오기」로 가져오세요」라고 알리고, 그 편의 콜시트에도
「⏳ 생성이 지연된 컷 2개 — 「결과 찾아오기」로 무과금 회수」 줄이 남습니다(회수는 조회라 공짜입니다).

**🧹 옛 테이크 한 번에** — 촬영장 필터 줄 오른쪽 끝에, 쌓인 옛 테이크가 두 장 이상일 때만
「🧹 옛 테이크 24장」이 나옵니다. 누르면 **지금 보이는 컷**(장·필터가 걸린 그대로)의 이전 테이크만
지웁니다 — 걸려 있는 그림과 판정은 그대로입니다. 실측이 근거입니다: 12컷을 세 번씩 다시 걸면
자산 36개·11.2MB이고, 컷마다 비우려면 «컷 열기 → 🧹 → 확인»을 서른여섯 번 눌러야 했습니다
(60컷 한 화면 180번). 확인창이 컷 수·장 수를 말하고, 비운 뒤 몇 MB가 줄었는지 알려 줍니다.

**장별 진도** — 대본실의 「장별 진도」 판(장이 둘 이상일 때, 펼침 여부는 기억됩니다)은 장마다
찍은 컷/전체와 NG 수를 진행 막대로 한 줄씩 보여줍니다. 20장 연재에서 콜시트의 한 줄(가장 덜 된
장, 네 장까지)로는 전체 판이 안 보이기 때문입니다. 장 이름을 누르면 정리대가 그 장만 보여주고,
**촬영장에서**를 누르면 촬영장이 그 장으로 맞춰집니다. 폰(390px)에서는 한 줄이 두 줄로 나뉩니다 —
위는 장 이름, 아래는 막대·숫자·버튼. 스무 장으로 열어 재 보니 한 줄에 다섯 칸을 밀어 넣으면
이름칸이 70px로 눌려 세로로 다섯 줄씩 찢어졌습니다(줄 높이 109px → 80px, 막대 60px → 95px).

**「새 장」 값은 관용해서 읽습니다** — 장의 유일한 기준은 컷의 `webtoon.pageBreak`인데, LLM은
프롬프트가 `true`를 요구해도 쪽 번호처럼 `1`을 쓰거나 `"true"`로 써 보냅니다. 예전에는 `true`가
아니면 조용히 버려서 20장짜리 대본이 «한 장»으로 들어왔습니다. 이제 켜려는 뜻이 분명한 값
(`1`·`"true"`·`"yes"`)은 새 장으로 읽고 몇 군데를 고쳐 읽었는지 한 줄로 알립니다. 끄는 값
(`false`·`0`·`"no"`·`"off"`)은 그대로 끕니다 — 없는 장을 만들어 내는 쪽이 더 나쁩니다.

**이 장 다시 쓰기** — 장마다 **✎ 다시 쓰기**가 그 장의 컷만 담은 프롬프트를 만들어 줍니다
(「id를 그대로 두라」·「컷 수를 늘리지 말라」·화풍·감독 노트가 함께 실립니다). LLM이 돌려준
JSON은 **다시 쓴 대본 넣기**에 붙여넣으면 **같은 id의 컷만 덮어씁니다** — 찍어둔 그림·OK/NG
판정·테이크는 그대로 남고, 조판실에서 손댄 말풍선도 새 대본이 주지 않으면 지켜집니다
(그래서 장 나누기가 풀리지 않습니다). 대본에 없는 id는 넣지 않고, ↩ 되돌리기로 한 번에 취소됩니다.

## 주요 기능 지도

- **조감독 리포트** — 컷과 관련된 항목에는 **「3장 · s37 보기」** 버튼이 붙어, 누르면 정리대가
  그 장으로 맞춰지고 그 컷으로 스크롤됩니다. 60컷 연재에서 컷 id만으로는 어디인지 감이 없습니다
  (검사 자체는 장을 모르는 순수 검사로 두고, 보여줄 때만 장을 붙입니다).
- **컷마다 무빙이 걸린 편을 몇 번을 봐도 무거워지지 않습니다** — 열두 컷에 2MB짜리 영상을 걸고
(24MB) 두 바퀴 상영한 실측입니다: JS 힙 10MB 그대로, 살아 있는 blob URL은 12개 → **2개**(지금
컷과 포스터) → 두 바퀴 뒤에도 2개, 페이지 오류 0. 지나온 영상은 제때 놓습니다(`vidplay` 스위트).

**아주 큰 필름캔도 빈 기기에서 그대로 열립니다** — 600컷에 그림을 걸어 만든 캔으로 실측했습니다:
7.1MB 캔은 내보내기 3.5초·들여오기 1.3초, 17.7MB(그림 60장)는 4.9초·1.9초이고, 컷 600개·찍어둔
그림·장 31개가 다 살아 옵니다(페이지 오류 0). 다만 들여오는 동안 화면이 **2.3초** 막히면서
아무 말이 없었습니다 — 새 기기에서 「내 작품이 살아 있나」를 확인하는 순간이라 그 침묵이 가장
무섭습니다. 이제 무거운 일 **전에** 「필름캔 「…」을 여는 중… (17.7MB)」이라 말하고, 끝나면
「장면 600 · OK 60」으로 갈무리합니다(`bigcan` 스위트).

**배우 얼굴이 카메라에 «실제로» 실리는지 말합니다** — 폰에서 「얼굴 없음」·「얼굴이 전송이 안 된다」는
보고를 세 갈래로 잡았습니다. ① 컷의 등장 배우 중 사진 없는 이가 있으면 예전에는 레퍼런스에서 **조용히**
빠졌습니다 — 이제 찍기 전에 「배우 「준」의 얼굴 사진이 없어 얼굴 없이 찍습니다」라고 이름으로 말합니다(같은
조합은 1분에 한 번). ② 폰 갤러리는 **webp·수 MB 원본**을 줍니다 — 그대로 base64로 실으면 형식을 안 받거나
요청이 거대해집니다. 이제 레퍼런스는 **1536px 이내 JPEG**로 맞춰 실립니다(EXIF 방향 반영, 2400×3200 webp가
1152×1536 JPEG 30KB로). ③ 「얼굴」 배지는 열쇠만 보고 켜졌는데, 사진이 저장소에서 사라져도 「얼굴」이라
했습니다 — 이제 **사진 블롭까지 있을 때만** 얼굴입니다. 덤: 어느 컷에도 켜지지 않은 배우는 장 수와 상관없이
「컷 카드의 배우 칩을 켜야 이 얼굴이 찍힙니다」라고 적습니다(`faceref` 스위트 · 폰 390px · 16체크).

**맨 위 / 맨 아래 버튼** — 긴 목록(대본실 120컷 = 45,000px)에서 엄지 한 번으로 끝과 끝을 오갑니다. 문서가
한 화면 넘게 길 때만 왼쪽 아래에 나오고(시사실처럼 짧은 방에서는 숨습니다), 폰에서는 하단 탭 위·토스트 옆에
자리해 서로 가리지 않습니다(토스트가 왼쪽 여백을 비워 둡니다). 이동은 «한 번에»입니다 — 어림 높이 카드가
실제 높이로 자리 잡은 뒤 두 프레임에 걸쳐 진짜 끝에 다시 맞춥니다. 키보드(Tab·Enter)로도 됩니다
(`scrolljump` 스위트 · 19체크).

**배우 둘째의 사진이 첫째를 덮어쓰지 않습니다** — 캐스팅 사진의 신원은 배우의 `ref`입니다(그 값이
사진 창고의 열쇠이자 저장 키의 재료). 그런데 `ref` 없는 배우에게 사진을 걸면 **파일명**이 ref가 됐고,
폰 갤러리·카메라는 사진마다 같은 이름(`image.jpg`)을 주는 일이 흔합니다. 그래서 폰에서 두 배우에게
차례로 사진을 걸면 둘이 같은 ref·같은 키를 갖고 **두 번째 사진이 첫 번째를 덮어썼습니다**(실측: 두 배우가
모두 두 번째 그림 — 「배우가 1명만 캐스팅된다」는 보고가 이것이었습니다). story.json이 두 배우에 같은
`ref`를 적어 온 경우도 같았습니다. 이제 ref가 없거나 다른 배우와 겹치면 **배우 id로 짓습니다**(`mi.jpg`,
권장 형식 그대로), 겹쳐 온 ref는 갈라 걸었다고 말하며, 반영할 때 파서가 「배우 「미」·「준」의 ref가
같습니다」라고 경고합니다. 상단 「배우 사진 올리기」로 이름이 안 맞는 사진을 여러 장 올려도 막다른
「직접 걸어주세요」로 끝나지 않고 **「누구의 사진인가요?」** 라고 번호·이름을 묻고, 그 메뉴에 **「새 배우 만들기」**가
늘 들어 있습니다(없는 이름을 적으면 그 이름의 새 배우로 세울지 묻습니다). 얼굴 없는 배우가 한 명이면 그 번호가 미리 채워져 있어 「「미나」에게 걸기」 한 번으로 끝납니다(이름을 고쳐 적으면 새 배우). 배우가 모두 얼굴을 가진 뒤에 온 사진은
바로 **「새 배우 캐스팅」** 을 묻습니다 — 예전에는 배우가 한 명이라도 있으면 사진으로 새 배우를 만들 길이 아예
없어서(0명일 때만 만들었습니다), 폰에서 첫 사진으로 배우를 만든 뒤 둘째 사진은 「파일명이 맞는 배우가 없습니다」로
끝났습니다. 그것이 「1명만 캐스팅된다」의 진짜 원인이었고, 위의 덮어쓰기는 그 옆의 결함이었습니다 —
`castdup` 스위트(폰 390px · 23체크).

**회수가 「다른 편의 같은 컷 번호」를 물어 오지 않습니다** — 「결과 찾아오기」는 MakeFun 기록에서
`name === 컷 id`인 레코드를 찾습니다. 그런데 **컷 번호는 편마다 다시 시작하고**(새 프로젝트는 언제나
s01입니다) 기록에는 어느 편의 것인지가 없습니다. 그래서 A편 s01을 찍은 날 B편 s01이 지연되면, 자동
회수가 A편 그림을 B편에 조용히 걸거나 「추가 과금 없이 OK」라는 말과 함께 남의 그림이 걸렸습니다 —
내용이 전혀 다른 그림이라 한참 뒤에야 알아챕니다. 이제 기록에 남은 **프롬프트를 이 컷의 것과 맞대어**
봅니다: 자동 회수는 다르면 가져오지 않고 지연으로 남기고, 수동 회수는 두 프롬프트를 나란히 보여 주며
「다른 편의 s01일 수 있어요 — 그래도 걸까요?」라고 묻습니다(판정은 감독의 몫). 같은 편의 결과라면
묻지 않습니다(`pullmix` 스위트). 실제 계정의 기록을 조회(GET·크레딧 0)로 읽어 확인했습니다 — 기록에는 보낸 프롬프트가 **380자 그대로** 남아 있어서(꼬리까지 일치), 정상 회수는 이 확인창을 만나지 않습니다.

**중단해도 「이미 나간 돈」은 회수할 문을 열어 둡니다** — MakeFun은 **시작이 접수된 순간** 과금합니다.
그래서 20컷 배치를 7컷째에서 중단하면 그때 폴링 중이던 컷(동시 2컷)은 코인이 이미 나가 있고,
카메라 쪽에서는 그림이 계속 만들어집니다. 예전에는 그 컷에 아무 표시도 남지 않아서(상태는 대기,
메모 없음) **「결과 찾아오기」 단추가 뜨지 않았습니다** — 장부에는 돈이 찍혔는데 회수할 문이 없어,
다시 찍으면 같은 그림에 두 번 냈습니다. 이제 접수된 뒤의 중단은 그 컷을 **지연**으로 표시하고
메모에 나간 코인을 적으며, 중단 알림도 「접수된 2컷은 코인이 이미 나갔습니다 — 「결과 찾아오기」로
추가 과금 없이 가져올 수 있어요」라고 셉니다(`stopbill` 스위트).

**컷씬(영상) 변환은 앱이 대신 가져올 수 없다고 말합니다** — 스틸은 MakeFun 기록에서 회수할 수
있지만 영상에는 그 기록 API가 없습니다. 컷당 수십 코인인데도 변환을 중단하면 장부 숫자만 늘고
컷에는 아무 말이 없었습니다. 이제 메모가 **나간 코인 · 앱이 못 가져온다는 사실 · 사람이 할 수 있는
길**(MakeFun 기록에서 내려받아 「🎞 영상 걸기」로 걸면 추가 과금 없음)을 함께 적습니다
(`stopvid` 스위트).

**찍는 중에 창을 닫아도 그 컷을 찾아올 수 있습니다** — 「촬영 중」은 메모리에만 있던 상태라, 배치가
도는 중에 창을 닫거나 새로 고치면 접수돼 돈이 나간 컷들이 다음번에 그냥 **대기**로 보였습니다
(편을 «옮길» 때는 막아 주는 자리가 있었는데, 창을 닫는 길에는 없었습니다). 이제 촬영 시작이 컷
기록에 «접수 중»을 남기고, 다음에 그 편을 열 때 그 표시가 남아 있으면 지연으로 바꿔
**「지난번에 찍는 중이던 2컷을 지연으로 표시했습니다」** 라고 말합니다. 「결과 찾아오기」는 조회(GET)라
공짜이므로, 접수 전에 끊겼더라도 손해가 없습니다(`stranded` 스위트).

**프롬프트를 직접 고친 컷은 그렇다고 말합니다** — 컷 카드의 프롬프트 상자는 조립본 전문으로 채워져
있어서, 한 글자만 고쳐도 그 전문이 그 컷의 프롬프트로 굳습니다. 그때부터 그 컷은 **화풍(프리셋
포함)·배우 외모·장소·카메라 고정·얼굴 고정 문구**에서 통째로 떨어져 나갑니다 — 대본을 아무리 고쳐도
닿지 않습니다. 그런데 화풍 프리셋 옆 잔글씨는 「다음 촬영부터 적용돼요」라고만 약속해서, 누아르로
갈아입힌 감독은 **왜 이 컷만 옛 톤인지** 알아낼 방법이 없었습니다(60컷 편에서 굳은 컷을 세거나
골라낼 자리조차 없었습니다). 이제 다섯 자리가 그 사실을 말합니다:

- 카드에 **「✎ 직접 쓴 프롬프트」** 칩이 붙습니다.
- 촬영장 필터에 **「✎ 직접 쓴 N」** 이 생겨 그 컷만 골라 볼 수 있고, 그 자리에서
  **「↩ 전부 기본 프롬프트로 (N)」** 로 한 번에 풉니다(확인창이 무엇을 잃는지 먼저 말합니다).
- 화풍 프리셋을 누르면 **「2컷은 프롬프트를 직접 고쳐 두어 이 화풍이 닿지 않습니다」** 라고 세어
  알리고, 잔글씨도 그 예외를 함께 적습니다.
- 조감독 리포트가 굳은 컷의 개수와 id를 알립니다.
- 개별 되돌리기에도 확인창이 섭니다 — 직접 쓴 글은 Ctrl+Z로 돌아오지 않기 때문입니다.

고쳤다가 **원래 글자로 되돌려 놓으면 스스로 풀립니다**(조립본과 같아지는 순간 ✎ 표시가 사라지고
다시 대본을 따릅니다). 마지막 컷을 되돌려 ✎ 필터가 사라지면 촬영장은 전체로 돌아옵니다
(`customprompt` 스위트).

**무빙(영상)을 바꿀 때는 앞 영상이 어디 남는지 말합니다** — 이미지는 바꾸면 앞 그림이 테이크로
남지만, 영상은 컷에서 빠집니다. 그런데 파일 자체는 저장소에 **고아**로 남고 지우는 문은
🧹 저장소 청소뿐입니다(실측: 다섯 번 걸면 영상 5개가 남고, 청소가 고아 4개를 잡아 1개가 됩니다).
영상은 수십 MB짜리라 그 사실을 숨기면 저장소가 조용히 찹니다 — 이제 교체 확인창이
**「이전 영상(약 2.0MB)은 이 컷에서 빠지고, 🧹 저장소 청소를 누를 때까지 저장소에 남습니다」**라고
크기까지 말합니다(`vidtakes` 스위트).

**테이크가 많이 쌓여도 단추가 묻히지 않습니다** — 다시 찍기를 반복한 컷은 테이크가 수십 장이
  됩니다. 99장이면 페이스 체크의 테이크 줄이 **33줄·1,529px의 벽**이 되어 그 아래의
  「이 컷만 다시」·NG 판정이 **화면 밖(y 1,779px)**으로 밀렸습니다(실측). 이제 **최근 열두 장만**
  펼치고 나머지는 「+ 37장 더 보기 ▾」로 접습니다(테이크는 최신순이라 가까운 것부터 보입니다).
  접힌 상태에서 단추는 y 525px — 스크롤 없이 닿습니다. 🧹 비우기는 여전히 전체 장수(49)를
  말하고, 비우면 지금 그림 한 장만 남습니다(`takes100` 스위트).
- **옛 테이크 비우기** — 페이스 체크의 「이전 테이크」 줄에 🧹 버튼이 있습니다. 다시 찍기를
  반복한 컷은 그림을 여러 장 붙들고 있습니다(실측: 여섯 번 = 6장 ≈ 1.9MB). 테이크는 되돌릴 수
  있는 자산이라 저장소 청소로는 지워지지 않으므로(그게 옳습니다), 컷 단위로 비웁니다 —
  지금 걸린 그림과 판정은 그대로입니다.
- 저장소를 **200MB 넘게** 쓰고 있으면 콜시트 맨 아래에 한 줄이 붙습니다(「저장소를 320MB 쓰고
  있어요 — 아무 컷도 안 쓰는 그림은 청소할 수 있습니다」 → 고급 열기). 실측 기준: 컷 한 장 ≈ 320KB,
  캐스팅 사진 ≈ 2.6MB이므로 20편 × 12컷 + 테이크면 수백 MB가 됩니다. 그 아래일 때는 조용합니다.
- **콜시트** — 대본실 맨 위에 오늘 이어갈 일(대기·NG·지연 컷, 얼굴 없는 배우, 끊어진 연결,
  백업 시기, 필름캔 기록 없는 작품, **장별로 남은 컷**(버튼이 「3장만 보기」처럼 그 장을 말하고,
  누르면 촬영장이 그 장으로 맞춰집니다 — **마지막 한 장만 남으면** 「「가을」만 남았습니다 — 2컷을
  찍으면 이 작품은 끝납니다」가 맨 위로 올라옵니다), 카메라 고정+reuse 오조합, 영상화 안 한 컷씬,
  배우단에 없는 얼굴, 아직 안 해본 인쇄본)이
  한 장으로 — 위 5가지만 펼치고 나머지는 접습니다. 각 줄에서 바로 그 자리로.
- **대본실** — 컷 카드/한 줄 목록(☰) 전환, **장별 필터**(장이 여럿일 때), 🎞 연속 동작 3컷(같은 배경·🔒 카메라 고정으로 A→B→C를
  만들어 잇고, 갈림길은 마지막 컷으로 옮깁니다), 🔍 검색·상태 필터, 필름 맵(분기 SVG, 노드 클릭 이동, 🔗 연결 모드 — 컷이 여덟 열을 넘으면 글줄처럼 줄바꿈합니다.
  100컷 선형 대본이 가로 12,042px(10.3화면)이던 것을 1,086px 한 화면으로 접었습니다),
  ↩ 되돌리기(Ctrl+Z, 30단계), ✨ AI 프롬프트(초안/이어쓰기), 캐스팅(사진 걸기, ✎ 프로필, 하차,
  ⭐ 전속 배우단 — 작품을 넘어 배우 재출연, 선반에서 📷 얼굴 교체·✎ 프로필 수정), 조감독 리포트,
  고급 JSON + 🧹 저장소 청소(**저장된 작품 전부**를 훑어 아무도 안 쓰는 그림·영상만 지웁니다 —
  20편을 쓰면서 스무 번 청소하게 만들지 않고, 목록에서 지운 작품이 남긴 그림도 여기서 잡힙니다.
  확인창이 「작품 N편을 훑어 … 고아 M개」로 말해줍니다).
- **촬영장** — 장이 여럿이면 **장별 필터**(3장만 골라 찍기 — 인쇄본과 같은 기준으로 셉니다)와
  **이 장만 촬영**(그 장의 대기 컷만 차례로, 크레딧 안내 먼저), **✎ 장 이름**(인쇄본 띠·목차에 함께 반영),
  카메라/해상도(1K·2K·1:1 정사각) 선택과 예상 크레딧, 🎬 카메라 시운전(무과금 점검), 대기 컷 일괄 촬영, NG만 다시, 페이스 체크
  모니터(캐스팅 대조, 테이크 A/B 슬라이더 비교·복귀, 표지 지정, 무빙 컷), 제작비 장부.
- **시사실** — 타자기 대사(속도·글자 크기 취향), 앰비언스·🎵 음악, 자동 상영, 이전(되감기·스와이프),
  ☰ 컷 목록(장이 여럿이면 **「장부터」 한 줄**로 장 단위 상영 · 썸네일 + 대사·화자·컷 제목으로
  걸러내기와 바로 점프. 20컷을 넘으면 대사로 걸러내는 칸이 생깁니다 — 60컷이면 목록만 5화면이라서).
  장 줄의 **⏹ 장 끝에서 멈춤**을 켜면 「장부터」가 「이 장만」이 되어 그 장 마지막 컷에서 멈추고
  「여기까지입니다 — 이어서 보기 / 여기서 멈추기」를 보여줍니다(엔딩 크레딧이 아닙니다. 연재를
  장 단위로 검토할 때 다음 장으로 넘어가 버리면 흐름이 끊기니까요).
  내보낸 시사본 HTML의 목록에도 **장 이름이 머리글로** 들어갑니다 — 시사본에는 찍은 컷만 담기므로
  장의 첫 컷이 아직 안 찍혔으면 그 장에서 처음 찍힌 컷에 이름이 걸립니다(빈 장은 나오지 않습니다),
  세이브 슬롯 3칸, 진행 n/m, 엔딩 크레딧, 포스터.

## 손에 익는 조작

열린 창은 무엇이든 **Escape**로 닫힙니다(겹쳐 있으면 맨 위 창만, 확인창의 Escape는 «안 하는
쪽»). 이 규칙이 없었을 때 몽키 테스트가 모달에 갇혀 앱의 3분의 1밖에 돌아다니지 못했습니다.

**창이 뜨면 초점이 창 안에 머뭅니다** — 확인창·입력창·설정·감독 수첩·페이스 체크가 떠 있는 동안
탭은 창 안을 돌고(마지막에서 처음으로 감쌉니다), 닫으면 열기 전 자리로 돌아옵니다. 예전에는 탭
두 번이면 초점이 뒤 화면으로 새어 스무 번 중 열여덟 번이 창 밖이었습니다(실측) — 보이지 않는
단추를 누르게 되는 상태였습니다.

**작업 영역으로 건너뛰기** — 키보드로 처음 탭을 누르면 「작업 영역으로 건너뛰기」가 먼저 잡힙니다
(마우스에는 보이지 않습니다). 대본실 첫 컷까지 탭 **42번**이었던 것이 이 링크로 **8~11번**이 됩니다.
랜드마크(main·nav·header)와 제목 단계도 확인했습니다(건너뜀 0). 글자 대비는 본문 15.6:1,
옅은 회색 6.8:1, 컷 대사 16.4:1, 단추 9.5:1로 모두 WCAG 기준을 넘습니다(실측).

**키보드로도 쓸 수 있습니다** — 세 방의 단추 140개를 훑어 «이름 없는 단추»가 없음을 확인했고
(아이콘만 있는 단추도 제목을 답니다), **키보드 초점은 앰버 2px 링으로 보입니다**. 브라우저 기본
링은 이 어두운 화면에서 검정(rgb(16,16,16))이라 사실상 보이지 않았습니다(실측) — 마우스 클릭에는
뜨지 않도록 `:focus-visible`만 씁니다. 입력칸은 기존대로 앰버 테두리와 옅은 광으로 알립니다.

브라우저 없이 esbuild로) / `stopbill`(배치를 중단했을 때 접수돼 돈이 나간 컷의 회수 문 — 모의 카메라) / `stopvid`(컷씬 변환 중단 — 앱이 못 가져온다는 사실과 사람이 할 수 있는 길) / `stranded`(찍는 중에 창을 닫았다가 돌아올 때 — 기록에 남은 «접수 중»을 지연으로) / `customprompt`(프롬프트를 ## story.json 예시 · 그록에게 콘티 맡기기

`examples/` 폴더에 형식 예시 4종(완전판·이어쓰기·최소·**소설 각색본**)과 필드 설명이 있습니다.
실제 파서로 검증돼 있으며 `npm run verify:examples` 로 다시 확인합니다. 자세한 형식은
[examples/README.md](examples/README.md).

**LLM이 만든 콘티를 붙여넣기 전에 검사**할 수 있습니다:

```bash
npm run lint:story -- 내콘티.json
```

파서 에러·경고와 함께 «파서는 통과하지만 결과가 상하는» 자리를 짚습니다 — 배경이 실리지 않는
컷(`back`·`action`에 `bg_prompt` 없음), `look` 없는 배우(한국어 이름이 영어 프롬프트에 섞인다),
60자를 넘어 인쇄본에서 잘릴 대사, 한 컷 뒤 끊기는 `sfx`, 첫 컷에서 닿지 않는 컷, 앞 컷과 shot이
다른 `hold` 등.

**그록에 스킬로 등록해 두고 소설 원고를 던지는** 길도 있습니다 —
[examples/grok-skill.ko.md](examples/grok-skill.ko.md)(그록에 넣을 지시문 전문)와
`release/grok-skill-webtoon-storyjson.zip`(지시문·스키마 요약·예시를 묶은 한 벌).
그 지시문은 여섯 장르의 원고를 실제로 각색시켜 **여섯 편 전부 파서 에러 0 · 규칙 위반 0**으로
검증했습니다.
