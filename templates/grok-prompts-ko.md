# 그록(Grok) 요청 프롬프트 틀 — 한글판

스튜디오는 **두 모드**로 나뉜다.

| 모드 | 하는 일 | 그록이 필요한 순간 |
|---|---|---|
| **소설 만들기 모드** (스토리·장면·검사 탭) | 스토리라인 → 장면 구성 → 이미지 프롬프트 → 승인 | 아래 틀 ①~⑦ |
| **뷰어 모드** (뷰어 탭) | 완성작을 비주얼 노벨로 감상 | 필요 없음 |

`{중괄호}` 부분만 채워서 **grok.com 에 통째로 붙여넣으면 된다.**
③·④는 스튜디오의 [지시문 생성] 버튼이 캐릭터 앵커까지 채워 **자동으로 만들어 주므로 그걸 쓰는 게 기본**이고, 아래 틀은 구조를 이해하거나 직접 쓸 때를 위한 것이다.

---

## ① 아이디어 → 스토리라인 만들기

```
너는 비주얼 노벨/웹툰 스토리 기획 파트너다. 한국어로 답해.

[아이디어]
{한 줄 아이디어 또는 소재. 예: 폐지 위기의 교내 라디오 방송부}

[원하는 것]
- 장르/분위기: {예: 청춘 성장, 잔잔하고 따뜻하게}
- 분량: 한 화 기준 장면 {10}개 분량
- 주인공: {간단 설명, 없으면 "네가 제안해줘"}
- 꼭 넣고 싶은 요소: {예: 옥상, 노을, 라디오}
- 피하고 싶은 것: {예: 새드엔딩, 폭력 묘사}

[출력 형식 — 이 형식만, 다른 말 없이]
1) 로그라인 1줄
2) 스토리라인 10~15문장 (기승전결이 보이게)
3) 주요 등장인물 2~3명 — 이름 / 나이 / 성격 / 외형 특징
   (외형은 그림 생성에 그대로 쓸 수 있게 구체적으로: 머리 모양·색, 눈, 복장, 시그니처 소품)
4) 주요 장소 1~3곳 — 이름 / 분위기 / 시각적 특징
```

→ 결과의 2)를 스튜디오 **[스토리] 탭 스토리라인 칸**에 붙여넣고 저장.
→ 3)·4)의 외형/장소 특징은 `project/manifest.json` 의 캐릭터·장소 `prompt_anchor` 에 영어로 옮긴다(그록에게 "위 외형을 영어 앵커 문구 한 줄로" 요청해도 된다).

## ② 스토리라인 다듬기 (개정)

```
아래는 내 비주얼 노벨의 스토리라인이다. 한국어로 답해.

[현재 스토리라인]
{스토리라인 붙여넣기}

[고치고 싶은 점]
- {예: 중반이 늘어진다 — 작은 갈등 하나 추가}
- {예: 결말을 더 여운 있게}

[출력]
수정된 스토리라인 전체(비슷한 길이) + 끝에 "변경 요약" 3줄. 다른 말 없이.
```

## ③ 스토리라인 → 장면 구성 (SCENES_JSON)

> **기본 경로**: [장면] 탭 → 수동 모드 → **[지시문 생성]** — 캐릭터/장소 앵커까지 자동 포함.
> 응답의 JSON 배열을 ② 칸에 붙여넣고 [장면 생성]. 아래는 직접 쓸 때의 뼈대.

```
너는 비주얼 노벨 연출가다. 아래 스토리라인을 정확히 {N}개 장면으로 분해하라.

[스토리라인]
{스토리라인}

[캐릭터 (speaker_id 는 반드시 이 목록의 id)]
- CHAR-001 {이름}: anchor="{영어 외형 앵커 원문}"
- CHAR-002 {이름}: anchor="{영어 외형 앵커 원문}"

[장소]
- LOC-001 {이름}: anchor="{영어 장소 앵커 원문}"

[규칙]
1. image_prompt 는 영어. 등장 캐릭터와 장소의 anchor 문구를 원문 그대로 포함할 것.
2. 이미지 안에 글자/말풍선이 생기지 않도록 image_prompt 에 텍스트 요소를 넣지 말 것.
3. dialogue 는 한국어, 장면당 1~4줄.
4. location_id 는 장소 목록의 id 중 하나.

[출력 형식 — SCENES_JSON_ONLY]
다른 말 없이 JSON 배열만 출력하라. 각 원소:
{"order":1,"purpose":"...","action_beat":"...","emotion":"...","time":"...",
 "location_id":"LOC-001",
 "camera":{"shot":"...","angle":"...","framing":"...","focus":"..."},
 "dialogue":[{"speaker_id":"CHAR-001","text":"..."}],
 "image_prompt":"..."}
```

## ④ 장면 하나의 이미지 프롬프트

> **기본 경로**: 장면 카드 → 수동 모드 → **[① 지시문 생성]** — 장면 계획·직전 장면 연속성·앵커까지 자동 조립.
> 응답 전체를 ② 칸에 붙여넣고 [프롬프트 저장]. 아래는 직접 쓸 때의 뼈대.

```
너는 웹툰 연출 감독 겸 이미지 프롬프트 작성자다.

[캐릭터 기준(원문 그대로 프롬프트에 포함)]
{영어 앵커}

[장소 기준(원문 그대로 포함)]
{영어 앵커}

[이번 장면]
- 목적: {장면의 목적}
- 행동: {인물이 뭘 하는가}
- 감정: {감정}
- 카메라: {shot / angle / framing / focus}
- 화풍: {예: 따뜻한 셀 셰이딩 웹툰}

[규칙]
- 이미지 안에 글자·말풍선 금지. 대사 영역은 하단 여백으로만 확보.

[출력 — 이 4개 항목만]
SCENE_PROMPT: (영어, 앵커 원문 포함, 붙여넣기용 한 문단)
NEGATIVE_PROMPT: (영어)
CONTINUITY_NOTES: (다음 장면으로 이어질 요소, 한국어)
DIALOGUE_PLACEMENT: (대사 빈 공간 위치, 한국어)
```

## ⑤ 캐릭터 시트 — Gate B (3면도+표정)

```
너는 캐릭터 디자이너다. 아래 캐릭터의 "캐릭터 시트"를 외부 이미지 AI 로 생성할 프롬프트를 만들어줘.

[캐릭터]
- 이름: {하리}
- 외형 앵커(프롬프트에 원문 그대로 포함): {17-year-old Korean girl, short brown bob hair, ...}
- 성격(표정에 반영): {씩씩하고 밝음}
- 화풍: {따뜻한 셀 셰이딩 웹툰}

[시트 구성]
- 전신 3면도(정면/측면/뒷면) + 표정 4종(기본/미소/놀람/울먹)
- 단색 배경의 캐릭터 시트 레이아웃, 인화 고려 고해상도

[출력 — 딱 2줄]
PROMPT: (영어 1문단)
NEGATIVE_PROMPT: (영어 1문단)
```

→ 생성된 시트는 사람이 승인 후 `manifest` 의 `reference_images` 에 등록하고, 이후 **모든 장면 생성에 레퍼런스로 첨부**한다(일관성의 1차 수단).

---

## ⑥ 리테이크 — 생성 이미지가 기준과 어긋났을 때

```
방금 생성한 장면 이미지가 기준과 어긋났다. 이미지 프롬프트를 수정해줘.

[기준 앵커(원문 유지)] {영어 앵커}
[현재 프롬프트] {붙여넣기}
[어긋난 점] {예: 머리색이 검정으로 나옴 / 파란 머리핀 없음 / 배경이 밤임}
[유지할 점] {예: 구도와 조명은 그대로}

앵커 문구를 원문 그대로 포함한 수정 SCENE_PROMPT 와 NEGATIVE_PROMPT 만 출력해.
```

## ⑦ 대사 톤 다듬기

```
아래 장면 대사를 캐릭터 말투에 맞게 다듬어줘. 한국어.

[캐릭터 말투]
- {하리: 씩씩한 반말, 감탄사 자주}
- {준: 무뚝뚝, 짧은 문장}

[대사]
{장면 대사 붙여넣기}

장면당 1~4줄 유지. 수정본만 출력.
```

### 인화까지 생각한다면 (팁)
- 이미지 생성 시 **긴 변 최소 1800px(엽서), 2250px(5×7), 3600px(8×10)** 로 요청 — 프롬프트에 "high resolution, {2048}px long edge" 식으로 명시하고, 생성 후 [장면] 카드의 **인화 배지**로 확인.
