# 감상본을 밖에 올리기 전에 — 프라이버시 경고와 비공개 대안

`tools/export_pwa.py` 의 안내는 "이 폴더를 정적 호스팅(GitHub Pages/Netlify 등)하면
폰에 설치할 수 있다"고 말한다. 기술적으로 맞다. 하지만 **그 순간 이 작품은 인터넷 공개물이 된다.**
개인 소장용으로 만든 연애 서사와 인물 이미지라면 그 결과가 되돌릴 수 없다.

이 문서는 ① 무엇이 실제로 올라가는지 ② 공개 호스팅의 위험 ③ 올리지 않고 폰에서 보는 방법을 정리한다.

---

## 1. 감상본에 실제로 담기는 것

`export_viewer.py` / `export_pwa.py` 는 **단일 HTML 안에 모든 것을 내장**한다
(`build_data()` 기준):

| 담김 | 내용 |
|---|---|
| ✔ | 작품 제목 (`manifest.title`) |
| ✔ | 캐릭터 **이름** |
| ✔ | 장면 목적문(`purpose`) |
| ✔ | **모든 대사 원문** |
| ✔ | **승인된 장면 이미지 전부** — base64 로 HTML 안에 박힘 (`--all` 이면 승인 안 된 것까지) |
| ✔ | 선택지·분기·엔딩 데이터 |
| ✘ | 인물과 나눈 채팅 로그(`project/story/talk_*.json`, `chatlog.json`), 상한을 넘겨 밀려난 아카이브(`*.archive.jsonl`), 그 요약본(`memory_*.json`) — 내보내지 않는다 |
| ✘ | API 키·토큰 — 서버에만 있고 감상본에 들어가지 않는다 |

즉 **채팅 기록은 안전하지만, 작품 전체(그림+대사)는 파일 하나에 통째로 들어간다.**
그 파일 하나만 유출되면 작품 전체가 유출된 것과 같다.

### 제작 중에 이미 밖으로 나가는 것 — 프롬프트, 그리고 **이미지**

감상본을 올리지 않아도, 제작 과정에서 이미지 공급자(MakeFun)로 나가는 것이 있다.
예전에는 **생성 프롬프트뿐**이었지만 지금은 아니다:

| 언제 | 무엇이 나가나 |
|---|---|
| 이미지 생성 | 프롬프트 문자열(화풍·앵커·장면 묘사) |
| 생성 + 캐릭터 레퍼런스가 **로컬 파일**일 때 | 그 레퍼런스 이미지가 공급자 스토리지(R2)에 업로드된다 |
| **업스케일** | **확대할 원본 컷 자체**가 업로드된다 — 업스케일 API 가 URL 만 받기 때문에 우회로가 없다 |
| `--upload` | 지정한 파일 |

올라간 파일은 **인증 없이 열리는 공개 CDN 주소**를 갖는다. 주소에 내용 해시가 들어가 추측은
어렵지만, §2 의 결론이 그대로 적용된다 — **URL 은 비밀이 아니다.**

도구가 걸어 둔 방어선

- **이미지가 아닌 파일은 올라가지 않는다.** 매니페스트·설정 파일을 실수로 지정해도 거부된다
  (`content_type` 을 명시해야만 통과). 이 저장소는 토큰 이름과 사적 자산을 다루므로 그 관문을 둔다.
- `https` 가 아닌 업로드·결과 주소는 거부한다.
- 같은 파일은 같은 주소가 되어 사본이 늘지 않는다.

내가 통제할 수 있는 것

- 레퍼런스를 보내고 싶지 않은 생성은 `--no-reference`.
- 레퍼런스를 로컬 파일 대신 **내가 고른 곳의 URL** 로 등록하면 업로드가 일어나지 않는다.
- **업스케일을 쓰지 않으면 컷 자체는 나가지 않는다.** 대신 인화 규격은 생성 시점의 크기로 묶인다
  (→ [PRINT_ORDER_GUIDE.md](PRINT_ORDER_GUIDE.md) §1 의 두 경로 비교).
- **올린 파일을 지우는 경로는 이 저장소에 없다.** 삭제는 공급자 계정·약관을 따른다.

## 2. 공개 정적 호스팅의 위험

GitHub Pages · Netlify · Vercel 무료 배포는 기본이 **전 세계 공개**다. 로그인도, 접근 제한도 없다.

**"URL 을 아무한테도 안 알려주면 되지 않나?" — 안 된다.** URL 은 비밀이 아니다.

- 검색엔진과 크롤러가 링크 없이도 도달한다(인증서 투명성 로그, DNS, 호스팅 업체 색인 등).
  `robots.txt` 나 `noindex` 는 **요청**일 뿐 강제력이 없다.
- 그 페이지에서 다른 사이트로 이동하면 `Referer` 헤더에 내 URL 이 실려 간다.
- 브라우저 동기화, 주소창 예측, 설치된 확장 프로그램이 방문 URL 을 수집할 수 있다.
- 한 번 공개된 페이지는 **삭제해도 캐시·아카이브에 남을 수 있다.** 내리는 것으로 되돌아가지 않는다.
- 저장소를 public 으로 만들어 GitHub Pages 를 쓰면, 배포물뿐 아니라 **커밋 이력 전체**가 공개된다.
  과거 커밋에 개인 대화 로그가 들어간 적이 있다면 지금 파일을 지워도 이력에 남는다.

추가로 확인할 것
- **PWABuilder 같은 외부 변환 서비스**에 URL 을 넣는다는 건, 그 서비스에 내 사이트 주소를 넘기고
  가져가게 한다는 뜻이다. 비공개로 두려는 페이지에는 쓰지 않는다.
- 생성 이미지의 **재배포 가능 여부는 이미지 AI 서비스 약관**을 따른다. 개인 소장과 공개 게시는 다른 행위다.
- 실존 인물을 닮은 이미지가 섞여 있다면 공개는 초상·명예 문제로 번질 수 있다.

## 3. 올리지 않고 폰에서 보는 방법 (권장 순서)

### ① LAN 직접 접속 — 아무 데도 안 올린다 (가장 안전, 기본값)

```
python tools/webapp.py --lan
```

같은 와이파이의 폰 브라우저에서 콘솔에 표시된 `http://192.168.x.x:8765/` 로 접속한다.
데이터는 내 PC 를 떠나지 않는다. 자세한 절차는 [PHONE_TUTORIAL.md](PHONE_TUTORIAL.md).

주의: LAN 모드는 **같은 네트워크의 다른 기기도 접속할 수 있다.** 집 와이파이에서만 쓰고,
카페·회사·공용 와이파이에서는 켜지 않는다. 다 보고 나면 서버를 끈다.

### ② 파일로 직접 넘기기

`output/viewer/*.html` (또는 `output/pwa/index.html`) 은 **자체 완결 파일**이라 인터넷 없이 열린다.
USB 케이블로 폰에 복사한 뒤 파일 앱에서 열면 된다.

> 메신저·메일·클라우드 드라이브로 "나에게 보내기" 하는 것도 결국 **제3자 서버에 업로드**하는
> 행위다. 공개 URL 보다는 낫지만 "아무 데도 안 올린 것"은 아니다.

### ③ 꼭 호스팅해야 한다면 — 접근 제어가 있는 곳에만

- 호스팅 업체의 **비밀번호 보호 / 접근 제어** 기능을 켠다(무료 플랜에서 제공되는지는 가입 전에 확인).
- 저장소는 **private** 으로 둔다.
- 검색 차단(`noindex`)은 보조 수단일 뿐, 접근 제어의 대체가 아니다.
- 다 본 뒤에는 배포를 내리고, 같은 URL 을 재사용하지 않는다.

### ④ 실물 인화 — 유출 위험 0

인화 마스터로 구워 사진으로 뽑으면 네트워크가 개입하지 않는다.
[PRINT_ORDER_GUIDE.md](PRINT_ORDER_GUIDE.md) 참고. (인화소 업로드도 제3자 전송이라는 점은 그 문서에 정리해 두었다.)

## 4. PWA 설치에 관한 기술적 사실 하나

PWA 의 오프라인 캐시(`sw.js`, 서비스 워커)는 **HTTPS 또는 localhost 에서만 등록된다.**
따라서 `http://192.168.x.x:8765/` 같은 LAN 주소로는 서비스 워커가 동작하지 않는다 —
"홈 화면에 추가"로 바로가기는 만들 수 있지만 오프라인 실행은 되지 않는다.

**오프라인으로 갖고 다니고 싶다면 호스팅이 아니라 ②번(파일 복사)이 정답이다.**
단일 HTML 은 서비스 워커 없이도 오프라인에서 그대로 열린다. 이미지가 파일 안에 들어 있기 때문이다.
