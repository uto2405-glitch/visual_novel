# 껐다 켰을 때 — 다시 켜는 법

두 대를 쓴다. **역할이 다르고, 필요한 때도 다르다.**

| 기계 | 하는 일 | 언제 필요한가 |
|---|---|---|
| **노트북**(LENOVO · 192.168.219.182) | 글 엔진(llama-server) + 웹 스튜디오 + 데이터 | **늘** |
| **데스크탑**(DESKTOP-06ACMT6 · 192.168.219.113) | 그림 엔진(ComfyUI) | **그림 뽑을 때만** |

3060 이 데스크탑에 있다. 그것만은 옮길 수 없어서 이렇게 갈린다 — **글은 노트북만으로 다 되고,
그림을 뽑을 때만 데스크탑도 켠다.**

---

## 먼저 한 번만 — 로그인하면 저절로 뜨게 해 두기

```powershell
powershell -ExecutionPolicy Bypass -File install_autostart.ps1
```

**왜 이게 먼저인가 — 실제로 당했다.** 2026-09-16 12:42, 윈도 업데이트가 노트북을 예고 없이
재부팅했다. 사람이 끈 것이 아니다. 그때 글 엔진(llama-server)과 웹 스튜디오가 같이 사라졌고,
둘 다 손으로 띄운 것이라 **다시 뜨지 않았다.** 폰에서 열어 본 사람은 왜 안 되는지 알 수 없다.

자동 시작을 걸어 두면 재부팅이 있어도 로그인 한 번으로 돌아온다. 끄고 싶으면
`-Remove` 를 붙여 다시 실행하거나, 실행 창에 `shell:startup` 을 치고 바로가기 하나를 지우면
된다. 그 바로가기 말고는 아무것도 바꾸지 않는다.

데스크탑 쪽 ComfyUI 는 이미 같은 방식으로 걸려 있다.

---

## 글만 쓸 때 (대화 · 스토리 · 장면 구성 · 감상)

1. 노트북을 켜고 로그인한다.
2. 끝. (로그인하면 `start_laptop.bat` 이 자동으로 돈다 — 글 엔진과 스튜디오가 같이 뜬다)
3. 폰에서는 노트북 화면에 뜬 주소를 연다.

직접 켜고 싶으면 바탕화면 아이콘이나 저장소의 `start_laptop.bat` 을 누른다.
이미 떠 있는 것은 다시 띄우지 않는다 — 두 번 눌러도 모델이 다시 적재되지 않는다.

## 그림도 뽑을 때

4. 데스크탑 **전원만** 켠다. 로그인하면 ComfyUI 가 알아서 뜬다.
   - 자동 시작을 끄려면 실행 창에 `shell:startup` 을 치고 바로가기 하나를 지우면 된다. 그것뿐이다.
5. 스튜디오가 알아서 찾는다. 머리말의 그림 칩이 `그림 연결됨` 으로 바뀐다.

### 방을 건너가기 싫으면 — 노트북에서 깨운다

```powershell
powershell -ExecutionPolicy Bypass -File wake_desktop.ps1
```

이미 켜져 있으면 아무것도 하지 않는다. 깨우면 ComfyUI 가 응답할 때까지 기다렸다가 알려 준다.

**되는 조건이 있다.** 매직 패킷은 랜카드에 전원이 남아 있을 때만 닿는다.

- **절전(잠자기)** 에서는 거의 언제나 된다 → 당장은 종료 대신 **절전**을 쓰는 것이 제일 쉽다.
- **완전 종료**에서도 되게 하려면 세 가지가 필요하고, 전부 사람이 해야 한다:
  1. BIOS/UEFI 에서 `Wake on LAN` 또는 `Power On by PCI-E` **켜기**
  2. 같은 화면의 `ErP Ready` / `Deep Sleep` **끄기** (켜져 있으면 전원을 완전히 끊는다)
  3. 윈도의 **빠른 시작 끄기** (종료가 사실은 최대절전이라 랜카드가 무장 해제된다)
     - 제어판 → 전원 옵션 → 전원 단추 작동 설정 → 현재 사용할 수 없는 설정 변경 → 빠른 시작 켜기 해제

확인된 것: 이 데스크탑은 유선 Intel I211 이고 매직 패킷 수신이 켜져 있으며, 윈도가 이 랜카드를
'깨울 수 있는 장치' 로 등록해 두었다. 노트북이 쏜 패킷이 실제로 도착하는 것도 확인했다
(102바이트 · 출발지 192.168.219.182). 남은 변수는 위의 세 가지뿐이다.

## 노트북은 자면 안 된다

노트북이 메인 호스트다 — 자면 폰에서 아무것도 안 된다. 한 번만 꺼 두면 된다:

- 설정 → 시스템 → 전원 및 배터리 → **화면 및 절전**: 전원 연결 시 절전 **안 함**
- 같은 화면의 **덮개를 닫을 때**: 아무 것도 안 함
- 장치 관리자 → 네트워크 어댑터 → 무선 어댑터 → 속성 → **전원 관리**:
  "절전을 위해 이 장치를 끌 수 있음" **체크 해제** (이게 켜져 있으면 화면은 켜진 채
  무선만 내려가고, 밖에서 보면 기계가 사라진 것처럼 보인다)

## 주소가 바뀌면

공유기가 주소를 새로 나눠 줘도 **PC 끼리는 이름으로 찾는다.** 그래서 대부분 아무 일도 안 일어난다.

한 가지만 알아 두면 된다 — **이름 해석이 방향마다 다르다.** 단순화하지 말 것:

| 어디서 → 어디로 | 되는 이름 | 안 되는 이름 |
|---|---|---|
| 데스크탑 → 노트북 | `LENOVO` | `LENOVO.local` |
| 노트북 → 데스크탑 | `DESKTOP-06ACMT6.local` | `DESKTOP-06ACMT6` |

**폰은 다르다.** 폰은 윈도 이름을 못 찾을 수 있으니 주소(숫자)로 연다. 스튜디오가 켜질 때
콘솔에 폰이 열 주소를 찍어 주므로 그걸 쓰면 된다.

폰이 갑자기 PIN 을 물으면 폰 주소가 바뀐 것이다. `start_laptop.bat` 안의
`-Trust "192.168.219.103"` 을 새 주소로 고치면 된다. 공유기 설정에서 폰 주소를 고정해 두면
그 일이 다시 생기지 않는다(공유기 관리 주소 `192.168.219.1`).

## 뭔가 안 될 때, 순서대로

```powershell
python tools/doctor.py        # 읽기 전용 30초 — 무엇이 꺼져 있는지 이름으로 말해 준다
```

- **글 관련 탭이 전부 먹통** → 노트북의 llama-server 가 안 떴다. `start_laptop.bat` 을 다시 누른다.
- **그림 칩이 `그림 끊김`** → 데스크탑이 꺼져 있거나 ComfyUI 가 안 떴다. 글 작업은 그대로 된다.
- **모델이 꺼진 채로 장면을 만들어야 한다** → 대화 화면의 [지시문 복사] 로 지시문을 가져가
  다른 기기·다른 AI 에서 답을 받고 [붙여넣은 것으로 장면 만들기] 에 넣는다. 모델을 부르지 않는다.
- **답이 안 온다** → 조립이 모델을 잡고 있으면 대화는 그 뒤에 온다(최대 15분까지 기다린다).
  화면이 "조립이 모델을 잡고 있어 답이 그 뒤에 옵니다 — 약 N분 남았습니다" 라고 말해 준다.
