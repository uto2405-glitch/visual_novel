# 인화 주문 실무 가이드 — 첫 주문에서 실패하지 않기

화면에서 예쁜 컷이 인화지에서 어둡거나, 얼굴이 잘리거나, 색이 딴판으로 나오는 이유는 거의
정해져 있다. 이 문서는 이 저장소의 도구로 구운 마스터를 **온라인 인화소에 실제로 넘기는 절차**다.

---

## 0. 3분 요약

1. `python tools/print_preflight.py` — 이 컷이 몇 인치까지 되는지 **먼저 확인**한다.
   원하는 규격에 모자라는데 **이미 승인한 컷**이라면, 재생성 말고 **업스케일**이다(§1 마지막 절).
2. `python tools/print_export.py --size 4x6 --contact` — 마스터를 굽는다.
3. 주문할 때 올리는 파일은 **`.jpg`** (TIFF 아님). 파일명은 `001_SCENE-001.jpg` 처럼
   **이야기 순서 접두사**가 붙어 나오므로, 업로더에서 이름순 정렬만 하면 순서가 맞는다.
4. 주문 옵션에서 **자동 색보정을 끈다.**
5. **무테(테두리 없음)** 를 고르면 가장자리가 잘린다는 전제로 만들어야 한다.
   잘리는 게 싫으면 `--mode fit` 으로 여백을 넣어 굽는다(§2).
6. 첫 주문은 **1~2장만** 테스트로 뽑아 보고, 만족하면 전체를 주문한다.

## 1. 해상도 — 뽑기 전에 판정부터

```
python tools/print_preflight.py            # 승인된 장면 전부
python tools/print_preflight.py --scene SCENE-003
```

판정 기준 (`tools/print_preflight.py`)

| 실효 DPI | 판정 | 뜻 |
|---|---|---|
| 300 이상 | 좋음 | 사진 인화 권장선. 손에 들고 봐도 선이 또렷하다 |
| 240~299 | 보통 | 액자에 넣어 조금 떨어져 보면 괜찮다 |
| 240 미만 | 업스케일필요 | 뽑으면 뭉개진다. **승인한 컷이면 업스케일**, 아직이면 더 크게 생성한다(아래) |

### 규격별로 필요한 최소 픽셀 (300DPI · 2:3 원본 기준)

| `--size` 값 | 실제 크기 | 최소 픽셀 | 2:3 원본의 잘림(cover) |
|---|---|---|---|
| `photocard` | 55×85mm (포토카드) | **670 × 1004** | 좌우 약 3% |
| `3x5` | 89×127mm | **1050 × 1575** | 위아래 약 5% |
| `a6` | 105×148mm | **1239 × 1859** | 위아래 약 6% |
| `4x6` (엽서) | 약 10×15cm | **1200 × 1800** | **0%** — 비율이 딱 맞는다 |
| `5x7` | 약 13×18cm | **1500 × 2250** | 위아래 약 7% |
| `a5` | 148×210mm | **1749 × 2624** | 위아래 약 5% |
| `8x10` | 약 20×25cm | **2400 × 3600** | 위아래 약 17% |
| `a4` | 210×297mm | **2481 × 3722** | 위아래 약 6% |
| `11x14` | 279×356mm | **3300 × 4950** | 위아래 약 15% |
| `namecard` | 50×90mm (명함) | **709 × 1063** | 좌우 약 17% |

"최소 픽셀"은 **2:3 원본이 확대 없이 그 규격을 채우는 데 필요한 크기**다(출력 픽셀 자체가 아니라).
`spec_sheet.json` 의 `upscaled: false` 를 보장하는 선이라고 보면 된다.

전체 목록과 별칭은 `python tools/print_export.py --list-sizes` 로 확인한다
(`엽서`·`포토카드`·`명함` 같은 한글 별칭과 `55x85mm`·`10x15cm` 같은 자유 규격도 받는다).

**핵심: 매니페스트 기본값 `min_long_edge_px: 1024` 로는 엽서도 못 뽑는다.**
1024px 를 300DPI 로 앉히면 긴 변이 약 3.4인치 — 4×6 엽서(6인치)에 한참 못 미친다.
실물 인화를 할 작품이라면 이미지 생성 단계에서부터 위 표의 픽셀을 목표로 잡아야 한다.

### ⚠ 해상도를 올릴 때 반드시 함께 올릴 값

매니페스트 두 곳을 **같이** 고친다.

```json
"output":          { "min_long_edge_px": 2250 },   ← 검사기 A3 기준 + 생성 요청 크기
"image_generator": { "max_long_edge_px": 2560 }    ← 생성 요청의 상한 (기본 2048)
```

`min_long_edge_px` 만 올리면 `makefun_client` 가 요청을 **상한값에서 잘라 낸다.**
2250 을 요청해도 2048 로 생성되고, 올려 둔 기준 때문에 그 장면은 검사기 **A3 FAIL** —
**과금은 되고 규격은 못 맞추는 최악의 조합**이다. 5×7(2250) · 8×10(3600) 둘 다 이 함정에 걸린다.
하드 상한은 4096 이라 그 위 값은 4096 으로 잘린다.

과금 없이 지금 설정을 확인한다:

```
python tools/makefun_client.py --check
  OK   생성 크기 1500x2250 (긴 변 2250px · 상한 2560px)
```

`상한` 이 목표 픽셀보다 작으면 아직 잘리는 상태다. 큰 값을 처음 쓸 때는 공급자가 실제로
그 크기를 받아 주는지 **한 장(`--n 1`)으로 먼저 시험**한다.

**비율이 2:3 이면 4×6 은 잘림이 없다.** 인물의 머리나 발끝이 잘리는 게 싫다면 4×6 이 가장 안전하다.
8×10 은 위아래로 17%가 날아가므로, 얼굴이 프레임 위쪽에 있는 컷은 `--anchor top` 을 쓴다.

### 이미 승인한 컷을 인화 규격으로 올리기 — 업스케일 vs 재생성

위 표를 보고 "지금 승인한 컷으로는 엽서가 한계"라는 결론이 났을 때 읽는 절이다.
지금 이 작품이 정확히 그 상태다:

| 승인 컷 | 선택 이미지 | 픽셀 | 300DPI 로 가능한 최대 |
|---|---|---|---|
| SCENE-001 ~ 006 (6장) | `*_a-2.png` | **1200×1800** | **엽서 4×6** (잘림 0%) |
| SCENE-007 | `mf_424c98_1.jpg` | **1080×1624** | **3×5** — 엽서는 270DPI("보통")까지만 |

길은 둘이다. **이미 승인한 컷이라면 업스케일이다.**

| | **업스케일 (권장)** | 재생성 |
|---|---|---|
| 명령 | `python tools/makefun_client.py --upscale SCENE-001` | 매니페스트 두 값을 올린 뒤 `python tools/makefun_client.py SCENE-001` |
| 그림 | **사람이 승인한 그 그림 그대로.** 픽셀만 커진다 | **달라진다** — 구도·표정·손·머리카락이 다시 뽑힌다 |
| 승인 게이트 | 선택본·승인 상태를 **건드리지 않는다**. 새 후보로만 저장된다 | 후보를 다시 고르고 다시 승인해야 한다 |
| 사전 준비 | 없음 (`min_long_edge_px` 를 올리지 **않는다** — 아래 ⚠) | `output.min_long_edge_px` + `image_generator.max_long_edge_px` 를 함께 상향 |
| 과금 | 장당 1회(업스케일) | 장당 1회(생성). 7장이면 7번 다시 낸다 |
| 결과 크기 | **응답이 정한다** — 배율을 요청하는 파라미터가 없다 | 요청한 픽셀(단, 상한에 깎일 수 있다 → 위 ⚠) |

**이미 승인한 컷에 재생성은 권하지 않는다.** 승인은 SCORECARD C(사람 시사)를 통과했다는
뜻이고, 재생성은 그 판단의 대상 자체를 갈아 치운다. 업스케일은 같은 그림의 픽셀만 키우므로
승인의 의미가 유지된다.

#### 규격별 — 지금과 확대 후 (300DPI · 2:3 원본 기준)

| 규격 | 300DPI 필요 px | 지금 1200×1800 | SCENE-007 (1080×1624) | 2배로 커지면 (2400×3600) |
|---|---|---|---|---|
| `photocard` 55×85mm | 670 × 1004 | 538DPI 좋음 | 485DPI 좋음 | 1076DPI 좋음 |
| `3x5` | 1050 × 1575 | 343DPI 좋음 | 309DPI 좋음 | 686DPI 좋음 |
| `4x6` (엽서) | 1200 × 1800 | **300DPI 좋음** | 270DPI 보통 | 600DPI 좋음 |
| `5x7` | 1500 × 2250 | 240DPI 보통 | 216DPI 업스케일필요 | 480DPI 좋음 |
| `a5` | 1749 × 2624 | 206DPI 업스케일필요 | 185DPI 업스케일필요 | 412DPI 좋음 |
| `8x10` | 2400 × 3600 | 150DPI 업스케일필요 | 135DPI 업스케일필요 | **300DPI 좋음** |
| `a4` | 2481 × 3722 | 145DPI 업스케일필요 | 131DPI 업스케일필요 | 290DPI 보통 |

마지막 열은 **"2배가 나왔다면"의 예상치**이지 약속이 아니다. MakeFun 업스케일에는 배율
파라미터가 없고(`{source_url, name}` 만 보낸다) 응답 스키마도 공개돼 있지 않다.
그래서 도구는 받은 파일을 직접 재어 결과를 알려 준다:

```
  업스케일 1200×1800 → 2400×3600
  이 크기는 300DPI 인화로 최대 8×10 까지입니다 (긴 변 12.0인치)
```

결과가 원본보다 크지 않으면 **`주의: 결과가 원본보다 크지 않습니다 — 과금됐는데 인화 규격은
그대로입니다.`** 가 뜬다. 그 경우 두 번째 장을 확대하기 전에 멈추고 판단한다.
**한 장으로 먼저 시험하고, 실제 배율을 확인한 뒤 나머지를 돌린다.**

#### 실제 절차 — APPROVED 장면을 확대해서 쓰기까지

```powershell
# 1) 확대 (유료 · 선택된 이미지 1장이 대상)
python tools/makefun_client.py --upscale SCENE-001
#    → images/raw/SCENE-001/SCENE-001_a-2_up.png   (원본 이름 + _up · 확장자는 결과에 맞춘다)
#      같은 컷을 또 키우면 …_up-2 로 붙는다 — 덮어쓰지 않는다
```

여기서 끝나지 않는다. **APPROVED 장면은 후보 목록이 잠겨 있어 확대본이 후보로 등록되지
않는다** — 파일만 저장되고 그 사실을 경고로 알려 준다. 승인된 컷을 사람 확인 없이 바꾸는
통로를 막아 둔 결과다. 확대본을 실제로 인화에 쓰려면 되돌린 뒤 다시 고른다:

```powershell
# 2) 되돌리기 — 선택본이 비워지고 상태가 IMAGE 로 내려간다
python tools/advance_scene.py revise SCENE-001 IMAGE --note "인화용 확대본 선택"

# 3) 폴더 스캔으로 확대본을 후보에 등록 — 스튜디오 [폴더 스캔] 버튼과 같은 동작
python -c "import sys;sys.path.insert(0,'tools');import scene_ops;print(scene_ops.register_images('SCENE-001'))"

# 4) 확대본을 선택하고 다시 승인
python tools/advance_scene.py select SCENE-001 <번호>
python tools/advance_scene.py approve SCENE-001

# 5) 확인 후 굽기
python tools/print_preflight.py --scene SCENE-001
python tools/print_export.py --size 8x10 --scene SCENE-001 --anchor top
```

아직 승인 전(`IMAGE`·`REVIEW_HUMAN`)인 장면이면 2~3단계가 필요 없다 — 확대본이 **자동으로
후보에 등록**된다. 어느 쪽이든 **선택은 사람이 한다.** 도구가 확대본을 대신 골라 주지 않는다.

> **`print_preflight` 는 선택된 이미지만 잰다.** 확대본을 저장만 하고 고르지 않았다면
> 판정표에는 여전히 옛 크기가 나온다 — 4단계까지 마쳐야 표가 바뀐다.

> ### ⚠ 업스케일 경로에서는 `min_long_edge_px` 를 올리지 마라
> 그 값은 검사기 **A3 이 선택 이미지의 긴 변을 재는 기준**이다. 8×10 을 노리고 3600 으로
> 올려 두면 **아직 확대하지 않은 장면 전부가 그 자리에서 A3 FAIL** 한다(승인된 장면 포함).
> 상향은 "앞으로 새로 생성할 컷"을 위한 것이고, 업스케일은 그것 없이 동작한다.

#### 실패했을 때 — 이미 낸 돈을 회수하는 법

업스케일은 시작한 순간 과금이다. 그래서 도구는 **작업 id 와 결과 URL 을 남긴다.**

| 증상 | 남는 기록 | 하는 일 |
|---|---|---|
| 시작은 됐는데 대기 중 실패·시간 초과(최대 5분) | `images/raw/<장면>/_gen_meta.json` 의 `task_id` | 잠시 뒤 다시 시도하거나, MakeFun 계정 화면의 업스케일 기록에서 결과를 확인 |
| 결과는 만들어졌는데 내려받기 실패 | 같은 파일의 **`result_url`** | **그 주소를 브라우저로 열어 받는다 — 다시 결제하지 않아도 된다** |

`logs/makefun_usage.jsonl` 에도 `kind: "upscale"` · `billable: true` 로 같은 줄이 남는다
(→ [SCHEMA.md](SCHEMA.md) §3.3). 지출을 되짚을 때 생성분과 확대분이 섞이지 않는다.

> **이름이 같은 다른 기능 두 개를 헷갈리지 마라.**
>
> | | 무엇 | 비용 |
> |---|---|---|
> | `print_export.py --upscale lanczos\|step\|auto` | **내 PC 에서 픽셀을 늘리는 리샘플**(§2 참조). 없는 디테일이 생기지는 않는다 | 무료 |
> | `makefun_client.py --upscale SCENE-001` | **MakeFun API 업스케일.** 새 후보 파일이 생긴다 | **유료** |
>
> 급할 때 `print_export --upscale step` 으로 굽는 것도 방법이지만, 그때는 `spec_sheet.json` 에
> `upscaled: true` 가 찍히고 §5 체크리스트에 걸린다. API 업스케일로 만든 컷은 **원본이 실제로
> 크므로** 그 표시가 붙지 않는다.

웹 스튜디오에서도 같은 동작을 장면 카드에서 실행할 수 있다(`POST /api/upscale` — CLI 와
**같은 함수·같은 중복 방지 잠금·같은 로그**를 탄다. 폰과 PC 에서 동시에 눌러도 과금은 한 번이다).

## 2. 마스터 굽기

```
python tools/print_export.py --size 4x6                  # 승인 장면 전부
python tools/print_export.py --size photocard            # 포토카드 55×85mm
python tools/print_export.py --size 5x7 --anchor top     # 잘림 기준을 위쪽으로
python tools/print_export.py --size 4x6 --contact        # 색인용 컨택트시트도 함께
python tools/print_export.py --size 5x7 --skip-upscale   # 해상도 부족분은 아예 굽지 않음
```

결과는 `output/print/<규격>/` 에 들어간다.

| 파일 | 용도 |
|---|---|
| `001_SCENE-001.jpg` | **인화소에 올리는 파일** (품질 95, 크로마 서브샘플링 없음) |
| `001_SCENE-001.tiff` | 무손실 보관본. 재작업·자가 인쇄용 |
| `spec_sheet.json` | 컷별 원본/출력 픽셀·크롭률·여백률·업스케일 방식 기록 |
| `contact_sheet.png` | 전체 썸네일 색인 (`--contact`) — `output/print/` 바로 아래에 생긴다 |

도구가 하는 일: 목표 규격·DPI 픽셀 계산 → **cover 크롭 또는 fit 여백** → LANCZOS 리샘플 →
sRGB 변환 → DPI 메타와 **sRGB ICC 프로파일**을 넣어 TIFF/JPEG 저장.

### 파일명 앞의 `001_` — 업로드 순서

기본으로 `scene_order` 3자리 접두사가 붙는다(`001_SCENE-001.jpg`). 인화소 업로더는 대개
파일명 순으로 줄을 세우므로, 이 접두사가 있으면 **앨범 순서가 이야기 순서와 같아진다.**
접두사가 싫으면 `--no-order-prefix`.

> 접두사 규칙을 도입하기 전에 구운 옛 마스터가 같은 폴더에 남아 있으면 도구가
> `참고: 접두사 없는 옛 마스터 N개…` 라고 알려 준다. **지우지는 않으니** 업로드 전에
> 직접 정리해야 같은 컷이 두 번 인화되지 않는다.

### 잘림이 싫을 때 — `--mode fit`

```
python tools/print_export.py --size 5x7 --mode fit                    # 흰 여백
python tools/print_export.py --size 5x7 --mode fit --bg "#f5f0e4"     # 작품 톤에 맞춘 여백
python tools/print_export.py --size 5x7 --mode fit --bg 245,240,228   # RGB 로도 지정 가능
```

`cover`(기본)는 규격을 꽉 채우고 남는 부분을 자른다. `fit` 은 **한 픽셀도 자르지 않고**
그림 전체를 넣은 뒤 남는 자리를 `--bg` 색으로 채운다. spec_sheet 에 `crop_pct` 대신
`pad_pct`(여백 비율)가 기록된다.

- 인물의 머리·발끝·소품이 프레임 가장자리에 붙은 컷은 `fit` 이 안전하다.
- `fit` 으로 구우면 **인화소에서는 무테(full-bleed)로 주문**하는 게 맞다. 내 파일의 여백이
  곧 테두리가 된다. 여기서 또 유테를 고르면 여백이 이중으로 생긴다.
- 어디를 자를지만 조절하고 싶다면 `fit` 대신 `--anchor top|bottom|left|right` 를 쓴다.

**장면별로 다르게 굽고 싶다면** 장면 파일의 `print` 블록이 명령행 값을 덮어쓴다:

```json
"print": { "crop_anchor": "top", "crop_mode": "fit", "pad_color": "#f5f0e4" }
```

한 번 정해 두면 다음 주문에서도 그 컷만 그 규칙으로 구워진다. (→ [SCHEMA.md](SCHEMA.md) §2.8)

**승인 후에도 크롭은 바꿀 수 있다 — `revise` 하지 마라(선택본이 지워진다).**
인화는 대개 승인한 뒤에 하므로, `print` 만 바꾸는 편집은 APPROVED 장면에서도 통과한다 —
승인 잠금의 **유일한 예외**다. 스튜디오에서는 [✂ 크롭 미리보기] 의 **기준** 을 바꾸면 그대로
저장되고, 파일을 직접 고칠 때도 `print` 블록만 고치면 된다.
크롭을 바꾸려고 `advance_scene revise` 를 부르면 승인이 풀리는 정도가 아니라
**`selected_image` 가 비워진다** — 인화 설정 한 글자 때문에 후보를 다시 고르고 다시 승인해야
한다. (→ [SCHEMA.md](SCHEMA.md) §2.1)

> **`--anchor top` 을 줬는데 아무 변화가 없다면** 그 장면에 `print.crop_anchor` 가 이미
> 적혀 있는지부터 본다. 장면 값이 명령행보다 세다 — 경고도 없이 조용히 이긴다.
> 그래서 `print` 블록은 **그 규칙이 정말 필요한 컷에만** 넣는다(모든 장면에 `"center"` 를
> 박아 두면 명령행 옵션이 통째로 죽는다).
>
> ```powershell
> # print 블록이 박힌 장면 찾기
> python -c "import json,glob;[print(f) for f in sorted(glob.glob('project/scenes/*.json')) if json.load(open(f,encoding='utf-8')).get('print')]"
> ```

### 색 — sRGB ICC 를 임베드한다

마스터에는 sRGB ICC 프로파일이 **파일 안에 들어간다.** 인화소가 프로파일을 읽어 색을
해석하므로, 프로파일 없는 파일을 업체가 임의 해석할 때 생기는 편차가 줄어든다.
굽고 나면 콘솔 마지막 줄에서 확인할 수 있다:

```
  색공간: sRGB ICC 임베드됨
```

`ICC 미임베드(littleCMS 없음)` 이라고 나오면 Pillow 가 littleCMS 없이 빌드된 환경이다.
그 경우에만 주문 시 "sRGB 파일"이라고 업체에 알려 주면 된다(대부분의 인화소는 프로파일
없는 파일을 sRGB 로 가정한다).

### 자가 재단 — `--bleed` + `--marks`

```
python tools/print_export.py --size 5x7 --bleed 0.125 --marks
```

`--bleed` 는 각 변에 여백을 더 붙이고, `--marks` 는 그 여백 **안쪽에** 코너 재단선을 그린다.
선을 따라 자르면 마크도 함께 잘려 나가 결과물에는 남지 않는다.
`--marks` 만 주고 `--bleed` 를 빼면 그릴 자리가 없어 안내 문구만 나온다.

**인화소 주문에는 쓰지 마라.** 업체도 자르고 내 파일에도 여백이 있으면 이중으로 잘린다.
집 프린터로 뽑아 커터로 자를 때만 쓰는 옵션이다.

### 해상도가 모자랄 때 — `--upscale`

```
python tools/print_export.py --size 5x7 --upscale step   # 다단계 확대 + 언샵 마스크
python tools/print_export.py --size 5x7 --upscale auto   # 외부 업스케일러 있으면 사용
```

| 값 | 하는 일 |
|---|---|
| `lanczos` (기본) | 한 번에 목표 크기로 LANCZOS 확대 |
| `step` | 1.5배씩 나눠 확대한 뒤 가볍게 샤픈 — 선화 뭉개짐이 덜하다 |
| `auto` | Real-ESRGAN 계열 실행파일이 있으면 먼저 돌리고 나머지만 LANCZOS. 없으면 `step` 으로 폴백 |

`auto` 는 PATH 에서 `realesrgan-ncnn-vulkan` / `realsr-ncnn-vulkan` / `waifu2x-ncnn-vulkan` 을 찾는다.
다른 자리에 설치했다면 환경변수 `UPSCALER_EXE` 에 실행파일 경로를 넣는다. 설치를 강요하지
않으며, 못 찾으면 그 사실을 알리고 계속 진행한다.

`⚠업스케일` 경고가 뜬 컷은 원본이 목표보다 작아 **여기서(내 PC 에서) 늘린 것**이다.
없던 디테일이 생기지는 않는다. 원본 자체를 키우는 게 정답이고, 길은 컷의 상태에 따라 갈린다:

- **이미 승인한 컷** → `python tools/makefun_client.py --upscale <장면>` (그림은 그대로, 유료)
- **아직 승인 전** → 매니페스트 두 값을 올려 더 크게 생성
- 급하면 `--skip-upscale` 로 그 컷만 빼고 주문한다

둘 다 §1 의 **"이미 승인한 컷을 인화 규격으로 올리기"** 에 절차가 있다.

> 재생성하기 전에 §1 의 **"해상도를 올릴 때 반드시 함께 올릴 값"** 을 먼저 적용한다.
> `max_long_edge_px` 를 안 올린 채 다시 생성하면 같은 2048px 이 또 나온다 — 과금만 두 번이다.

### 일부만 굽기

```
python tools/print_export.py --size 4x6 --scene SCENE-003              # 한 장면만
python tools/print_export.py --size 4x6 --only SCENE-001,SCENE-004     # 여러 장면만
python tools/print_export.py --size 4x6 --all                          # 승인 전 컷까지 전부
```

`--only` 는 갤러리에서 ★ 로 골라 둔 컷만 뽑을 때 쓴다(★ 목록은 `project/favorites.json`).
`--all` 은 아직 승인 도장을 찍지 않은 장면까지 포함하므로, **주문용이 아니라 시험 인화용**이다.

## 3. 주문할 때 고르는 옵션

### 파일 형식 — **JPEG 로 올린다**
많은 온라인 인화 업로더가 TIFF 를 아예 안 받거나, 받아도 자기들이 변환한다.
우리가 구운 `.jpg` 는 품질 95 · 서브샘플링 없음이라 눈으로는 무손실과 구분되지 않는다.
TIFF 는 내 보관용으로 남겨 둔다.

### 색보정 — **끈다**
주문 페이지에 "자동 색보정 / 자동 밝기 / 오토 컬러" 같은 옵션이 있으면 **해제**한다.
이 파이프라인은 SCORECARD C 의 `print_quality`·`style_match` 를 사람이 눈으로 승인한 톤이다.
인화소의 자동 보정은 인물 사진 기준으로 살색을 밀거나 채도를 올려서, 승인한 화풍을 무너뜨린다.
(보정을 끄면 결과가 내 화면과 다를 때 원인이 내 파일에 있는지 인화소에 있는지도 분리된다.)

### 무테 / 유테

| | 무테 (테두리 없음, full-bleed) | 유테 (흰 여백) |
|---|---|---|
| 느낌 | 사진 같음. 액자·앨범에 잘 맞음 | 폴라로이드 느낌. 굿즈 감성 |
| 잘림 | **가장자리 2~3mm 가 잘린다** | 잘리지 않음 |
| 주의 | 인물 얼굴·손·중요 소품이 가장자리에 붙어 있으면 위험 | 여백 때문에 실제 그림이 조금 작아짐 |

**무테로 주문할 거면 `--bleed`·`--marks` 를 쓰지 마라.** 둘은 **내가 직접 재단할 때** 쓰는
옵션이다. 인화소도 자르고 내 파일에도 여백이 있으면 이중으로 잘려 나간다.
자가 인쇄해서 커터로 자를 때만 `--bleed 0.125 --marks` 를 쓴다.

여백을 원하는데 인화소의 유테는 마음에 안 든다면, `--mode fit --bg` 로 **내가 고른 색의**
여백을 그림에 직접 넣고 무테로 주문하는 방법이 있다(§2). 여백 색까지 작품 톤으로 맞출 수 있다.

### 용지
- **유광**: 색이 진하고 쨍하다. 셀 셰이딩 웹툰 화풍과 잘 맞는다. 지문이 남는다.
- **무광**: 차분하고 지문이 안 남는다. 액자용.
- **반무광**: 무난한 절충.

처음이라면 같은 컷을 유광·무광 한 장씩 뽑아 비교하는 걸 권한다.

### 크기 선택 요령
- 처음 뽑아 본다 → **4×6**. 싸고, 2:3 이라 안 잘리고, 실패해도 타격이 없다.
- 책상에 세워둘 것 → 5×7.
- 지갑·다이어리에 넣고 다닐 것 → **photocard**(55×85mm). 필요 픽셀이 670×1004 로 가장 낮아
  해상도가 모자란 컷도 살릴 수 있다.
- 액자용 대표 컷 → 8×10 (단, 해상도 3600px 이 필요하고 위아래가 많이 잘린다).
  지금 컷은 1200×1800 이라 **그대로는 못 뽑는다** — §1 의 업스케일로 원본을 키운 뒤 주문한다.

## 4. 인화소에 파일을 올린다는 것

온라인 인화 주문은 **내 이미지를 업체 서버에 업로드**하는 행위다.
공개 웹에 올리는 것과는 다르지만 "내 PC 를 벗어나지 않는다"도 아니다.
개인적인 서사가 담긴 컷이라면 업체의 보관 정책을 한 번 확인하고,
주문 완료 후 계정에서 업로드본을 삭제할 수 있는지 살펴보자.
